# 扩量训练回归定位 · 2026-10-11

检查结论：Memory v5 的主要失败已经出现在本轮训练样本自身，不只是外部测试分布变化。多候选输入与真实业务字段都会触发相关性判断接近 50%；单纯补角色提示、调温度、提高计算精度或拆开问题调用无法修复。当前证据支持优先重做记忆相关性的输入表示、训练课程及验证覆盖，不能据此宣称已找到唯一内部根因。

正式服务仍为 **Router v3 / Executor v6 / Memory v2**，三者 ready。检查没有修改权重、阈值或服务，没有追加训练或调用教师 API。

## 实验与边界

在 lab data 盘加载独立模型副本，使用 GPU 1；读取已有冻结诊断和少量原训练/测试样本。第一组比较新旧 Memory，在 134 个状态上测试原表示、角色提示、完整原文、角色与完整原文、来源文字前缀、逆序以及候选隔离。另对 Router 8 条固定边界诊断比较原上下文、移除历史、将历史拼入当前文本。

第二组对 Memory v5 的 34 个状态比较 FP16 / FP32 与多问题并行 / 单问题调用。第三组检查 20 个公开训练来源对照，以及 1/2/3/4/8 个纯用户候选和实际业务元数据。四个 checkpoint 的权重哈希在加载前后均一致。原输入、完整结果和日志留在服务器 `datasets/public-scale-round6/diagnostics`，本地只保存汇总。

原来的整条状态评测可能同时检查相关性和 temporal_need；这里为定位只保留 relevance 任务。因此相关性子集数字不能替代原评测总分。新增固定事实的探针用于因果对照，训练样本用于拟合检查，均不是新的独立准确率或临床验证。隔离候选会将任务映射到 relevance_0，报告中的可用率使用该任务原有校准，不能直接将该表示部署到现有契约。

## Memory：排除的因素

| 对照 | 实测结果 | 能支持的结论 |
| --- | --- | --- |
| 校准前后 | 中文四候选原始平均置信度 0.5012，校准后 0.5015 | 约 50% 已存在于原始概率，温度不是主要来源 |
| 状态和问题预算 | 三组实验均无状态截断、问题头截断、选项合并 | 不能将这些失败归因于本次输入被截断 |
| 角色提示 / 完整原文 / 候选逆序 | 四候选可用正确仍 0/4；改编证据组仍 0/30 | 只调整这些提示没有解决问题 |
| FP16 → FP32 | 四候选两种精度均 0/4；原始平均置信度均约 0.5012 | 没有发现精度导致的概率塌缩 |
| 同一状态，多问题 → 单问题 | 结果与概率基本一致；FP32 对照汇总一致 | 不是将多个问题放在一次调用中的批处理错误 |

校准正温度不改变最大概率选项，客户端下限依然是 0.85。降低阈值无法解决相关性事实判断错误；本次没有尝试通过降阈值增加覆盖。

## Memory：关键失败

| 数据 / 表示（Memory v5） | 整组全部相关性正确 | 整组可用正确 |
| --- | ---: | ---: |
| 冻结中文四候选，原状态 | 0/4 | 0/4 |
| 同上，每条候选隔离判断 | 4/4 | 4/4 |
| 改编英文来源对照，原状态 | 0/30 | 0/30 |
| 同上，每条候选隔离判断 | 3/30 | 0/30 |
| 20 个公开来源训练状态，原表示 | 0/20 | 0/20 |
| 同上，把助手同文替换为无关文字 | 0/20 | 0/20 |
| 同上，每条候选隔离判断 | 10/20 | 4/20 |
| 抽查 20 个旧模板测试状态，原表示 | 18/20 | 17/20 |

20 个训练状态含 60 个相关性标签，原表示正确 40/60、弃权 40/60。用户事实与助手同文候选的 40 项全部低置信度；其中 20 个用户正例未被正确识别。即使移除助手同文，仍未恢复完整判断，说明不能把问题只归因于重复文字。此前“验证准确率 100%”来自旧合成课程，并未检验新增公开来源课程的拟合和业务格式覆盖。

新固定事实探针中，仅有一条用户原话、最小输入时，Memory v5 可以正确识别“每周四游泳”；加上真实检索返回的 id、observedAt、sessionId、source 等字段后，同一事实也降至约 50%。在 2/3/4/8 条纯用户候选中，最小表示与业务表示均没有可用整组结果；与候选是否为助手无关。该探针是一组固定事实，显示格式敏感性，不能量化所有生产请求的失败比例。

应用检索候选只来自用户原话，每轮最多 4 条；来源对照仍需要保留为训练边界，但实际训练还必须覆盖纯用户批次与业务字段。本轮 2508 个训练候选组中，3 条候选 2275（90.7%），8 条 220、2 条 8、1 条 5、4 条 0。缺少四候选是明确差异，但三候选训练拟合也失败，所以补四候选本身不够。

## Router：近期上下文退化

固定风险缓和案例中，保留近期明确自伤历史时，Router v3 正确判断 elevated，v4 判断 low（校准概率约 0.9994）。移除历史后，两个版本都判断 low；将历史简单拼入当前文本也不能修复 v4。原状态没有发生截断。

这支持 v4 未充分保留近期风险语义的解释；不支持用简单拼接历史替代现有结构。类别不均衡可能参与其中，但没有进行平衡训练对照，不能断言它是唯一原因。

训练审计只按关键词筛查：45 条历史包含自伤等关键词，其中 elevated 43、urgent 1、未含风险任务 1，没有 low 标签。此筛查不等于人工审核，不能排除其他隐性错标；但目前没有证据证明这些显式历史案例被教师直接标为 low。全体风险训练标签 low 占 92.7%，而近期风险上下文正例很少，仍需加强这一课程与独立验证。

## 下一步实施建议

1. **Memory 输入契约先改为明确的 query / 单条 candidate 证据对。** 用同一个相关性任务逐条评分，显式携带来源角色；业务 ID 与时间等追溯元数据保留在应用映射，模型输入只带确实需要判断的字段。是否引入候选时间应按时间问题单独定义。本次候选隔离只在部分中文案例有效，因此新表示仍需要重新训练、校准和独立验证，不能直接套用 v5 上线。
2. **增加公开来源课程的拟合与独立评测。** 训练拟合抽查只是排错；正式校准/验证应使用未入训练的完整会话分组，覆盖自然原话、不同长度、纯用户候选、角色同文、无关近似、缺失和矛盾证据。继续保留旧课程，但不能只靠旧模板选模型或设置门槛。
3. **Router 补当前否定与近期风险并存的对照。** 提高该类和专业渠道需求的课程覆盖，保留普通交流回放；逐例检查风险漏判与专业支持请求，不能只比较总体错误数。
4. **先跑小规模课程验证，再追加完整训练。** 先确认新表示在训练集能拟合、在未见事实与实际业务输入上可用，再扩量。Executor 的三个部分行动漏判保持独立修复，不让整体改善掩盖这些失败。

本次完成诊断，尚未实现上述契约变更或新训练。当前正式模型保持 v3 / v6 / v2。
