# JEV式记忆生命周期与4B微调计划

状态：基础已实现并完成两轮4B专项实验及只读旁路验证。当前分支 `feat/jev-memory-lifecycle` 从冻结标签 `freeze-20261015-memory-baseline`（提交 `6bf5885`）创建。正式 Memory 权重、读取链路与数据库保持基线；实验结果和未完成范围见 [第二轮报告](memory-lifecycle-v2-20261016.md)。

## 模型边界

当前 Memory 为 `psych-memory-qwen4b-lora-20261012`，采用有限候选/二元判别契约，已承担分类、原话相关性和证据充分性判断。它保留 JEV 的控制面思路，但不是完整 Jev-Mem 复现；Qwen 权重本身也不能直接称作 JEV 本体。

后续需要的是同一4B规模上的专项 LoRA 微调，而不是从头预训练。优先研究从现有 Memory adapter 继续微调并回放旧任务；若出现明显遗忘，再与同基座新建 LoRA 做对照。新旧模型分目录保存，保持旧适配器可回滚。Router、工具 Executor、目标 Executor 与原始0.6B重排器不在本轮重训范围。

## 控制器新增任务

采用有界、可审查的二元判断，最终数据库动作由程序结合多项结果决定。第一版已冻结独立契约 `psych-memory-lifecycle-v1`，新增 write_worthy、grounded、duplicate、supersedes、conflict，保留旧七项任务及原 renderer。正式服务仍使用 `psych-memory-v4`。

| 判断 | 输入 | 边界 |
| --- | --- | --- |
| 长期保留价值 | 来源原话、时间、候选记忆、用户明确记住/不记住指令 | 不把单次心情变成长期性格；没长期价值仍可留在近期信息窗口 |
| 重复或兼容补充 | 新候选与少量同账号已有记忆 | 同主题不等于同事实；重复只补证据，不增加副本 |
| 明确更正/替代 | 新旧原话、主体、属性、时间范围 | 必须有明确同属性变化；新消息时间更晚本身不能证明替代 |
| 冲突或不宜合并 | 新旧候选与来源 | 保留矛盾和独特细节；无法判断时保持分开 |
| 候选表述有来源支持 | 原话与提取出的候选记忆 | 不将助手建议、他人经历、假设或引用写成用户事实 |

分类、relevance、evidence_sufficient继续保留回归；temporal_need当前未参与在线控制，不因新增训练自动启用。新任务不能仅凭现有模型打过分类标签就视为已经具备。

## 存储与处理方向

- SQL消息为权威来源，记忆条目引用消息ID、必要原文区间、主体和时间范围，避免再次复制所有完整用户/助手文本。现有receipt的业务幂等凭据先保持。
- 近期信息独立于长期保留门槛，确保“今天很高兴”等事实在近期回顾中可见；消息已保存但后台未处理时，沿用近期SQL桥接。
- 活跃记忆包含事实/偏好/事件及证据引用，具备状态、版本和替代关系。目标进度通过目标ID读取权威记录，不再生成一份独立进度事实。
- 程序根据受控候选决定skip/add/support/replace/keep-separate；用户明确删除或拒绝长期记忆的要求优先于价值判断。低置信度不覆盖旧事实，保留近期来源待核对。
- 整理和复杂摘要在后台按批处理，普通控制判断不增加逐轮生成模型调用。先用现有数据库和少量关系表，不引入新的图数据库或多Agent后台。
- 热记忆和上下文有预算；归档退出默认检索，历史按需回源。归档不等于删除，完整聊天保留仍会增长；用户删除需传播到派生索引与缓存。

## 数据和训练

1. 先冻结候选结构、动作约束和少量人工审核的边界用例，再制作训练课程。
2. 按来源会话/账号/事实族分组后划分train、calibration、validation、test；同一原话的改写、反事实和新旧记忆配对不能跨分区泄漏。
3. 重点加入临时拒绝与稳定偏好、明确更正与单纯新事件、重复提问、混合主体、否定、时间范围、来源不支持和“应保持分开”等困难负例。真实用户聊天不自动作为训练数据。
4. 旧任务样本混入新课程，保留原冻结挑战集，不把它们回灌训练。新增任务建立独立留出评测，不能只看总体准确率掩盖更正误覆盖。
5. 使用现有Memory训练器的独立模型环境，必要的契约扩展与服务renderer须同步版本化；训练/校准/阈值选择分开，不沿用旧任务的接受阈值假设。
6. 服务器源码、数据、缓存、日志和检查点全部位于 `/home/ubuntu/data/psych-agent-routing-20261009/` 的新实验目录。第一轮已在独立目录完成，不覆盖旧模型。

## 接入门槛

先做“原话检索 / 结构化记忆 / 结构化记忆+控制器”三组对照，在相同数据和候选/上下文预算下检查：

- 今天心情、稳定偏好、用户更正、历史变化的召回与答案依据。
- 错误保留、错误合并、错误覆盖、错主体和遗漏关键细节的比例；原始模型与应用约束后的收益分别报告。
- 旧任务错误接受、弃权与冻结挑战是否退化。
- 每用户活跃条目数、重复率、索引/上下文体积、模型调用数、后台吞吐以及端到端P50/P95。

新模型先旁路记录决策，不改正式事实；离线通过后再小范围执行受控写入。数据库使用版本检查、幂等和可回退迁移。正式接入必须保留旧配置和权重引用，Git切回基线不能替代数据回退。

## 设计来源

- [Jev-Mem](https://arxiv.org/html/2609.23986v1)：独立控制面、关系组织、检索预算/充分性/停止和保留原始观察的整理。
- [Mem0 Dream](https://docs.mem0.ai/platform/features/dream)：提取和生命周期整理分离、合并与替代的追溯关系。
- [Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)：有界核心记忆与可回查历史分层。

本方案是面向当前项目的工程取舍，不宣称完整复现上述系统。第一轮新增任务开发挑战从47/60到53/60，但旧relevance从113/116降到111/116，因此不替换正式模型；目前也未减少正式原话索引的存储量。

第二轮新任务HTTP开发挑战160/180→169/180，错误接受16→9；但relevance为112/116，仍低于正式模型的113/116，因此新候选仅对1个合成账号旁路启用，正式检索与写入继续保持基线。
