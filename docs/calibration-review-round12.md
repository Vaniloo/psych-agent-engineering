## 新发现：校准前四位小数舍入

检查实际安装的 Laya 0.4.1 源码，`_decode_answers` 把概率保留四位小数，项目随后才应用温度。很小的概率被变成 0、较大概率变成 1，会丢失温度校准需要的尾部信息。

例如八选一 logits 为 `[10, 0, …, 0]`，小概率都被舍为 0。温度 5 时，未舍入分布的最大概率约 0.514；舍入分布经现有计算仍接近 1。因此先前“错误回答输出概率为 1”的统计描述的是 **Predict 接口舍入后的值**，不能当成内部精确置信度。旧数值与诊断原样保留，没有追改历史结果。

新增仅用于离线的版本锁定解码器，从同一次 forward 的 option logits 计算 float64 softmax，原返回值保留，附加未舍入分布。检查版本、私有接口、候选排列、内部中性温度及原回答一致性；不兼容时失败。未修改服务器 site-packages、权重或正式推理服务。

记录范围修订，另冻结 20 条带依据的新表达，在原 cohort 上重新拟合；前 40 条此时不再称为精度分支的盲测。三路对照为“舍入+旧校准”“未舍入+旧校准”“未舍入+新分类校准”：

精度问题确实影响接受状态和拟合温度。修正读取后，目标候选的一部分答对弃权可以通过重新校准恢复，但错误接受也会增长；新 20 条中仍有风险关键错误，旧回归仍有关键错误。没有方案满足接入要求。温度不会改变最大概率的类别，不能代替身份与来源辨识训练。相同 legacy/cohort test 上，两次运行的选择逐项一致，证明精度分支没有冒充分类提升。
