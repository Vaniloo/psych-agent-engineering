# 联网续问与调用协议泄露修复 · 2026-10-18

## 复现与原因

原会话先发“搜一下今天天气怎么样”，助手追问城市；用户补充“广州”后，只调用了角色语气参考，没有真正联网，并输出了含`search_weather`的DSML协议。

原联网前置匹配只覆盖“搜索/联网”等表达，漏掉“搜一下”；语义判断只看本轮文本，不看尚待补充的同会话请求。“广州”因而未获得联网权限。回答生成阶段随后自行写出了未注册的工具调用格式，旧流式代码把全部文本直接展示和保存。DSML不是已执行工具的回执，也没有被应用执行。

## 实现

- `web_policy.py`：补充口语入口；只有本轮有查询线索或同会话近期存在外查请求时才问语义模型。传入最多6条、每条最多600字的用户/助手消息，以及上海时区的当前日期；角色卡、用户画像、长期记忆不参与这次续问解析。
- 语义模型区分执行、补充信息、普通话题和判断不可用。缺少必要地点先澄清；识别“广州”是同会话待完成天气请求的补充后，生成完整查询词，并刷新实时查询。
- 地点必须有实际用户原话支持：地点/引用非空、原话真实包含该地点；助手推测或角色背景不能证明用户位置。不维护城市名词典，不自动定位。
- 外部公开查询暂停无必要的隐式跨会话背景读取；明确的个人记忆请求仍保留自身链路。联网仍走原有权限、预算、执行和观察节点。
- `response_protocol.py`：流式保留可能的内部标签前缀，跨分片识别DSML、tool_call、function_call等格式；普通文本无需固定长度缓冲。内部协议不会输出给用户，也不会被解释为工具执行。
- `response.py`：剔除历史助手的协议文本，首次泄露最多重新生成一次；若此前已显示普通文字，用`reply_reset`清空该回复正文，工具活动仍保留。再次泄露则给出自然语言失败说明，不无限重试。真实网络断流仍遵循原有失败语义。
- 前端历史显示与复制都隔离已有无效协议，保留数据库原始记录。用户自己输入的文本不经过助手回复替换。

回答提示同步禁止虚构工具，明确：搜索缺参数要追问，判断/执行不可用要说明本次未完成；不能用普通知识冒充实时天气。

## 验证

- Python完整741项通过；前端5个测试文件、相关JS语法、Ruff和差异检查通过。未修改Java后端，沿用上轮91通过/1跳过记录。
- 专项覆盖多种协议及所有二段切分位置、逐字符分片、正常Markdown/数学符号、已有可见文字后的重置、最多一次修复、历史协议剔除、虚构地点拒绝、口语查询、城市补充、新会话隔离及拒绝联网。
- 合成账号经前端代理4轮实际SSE：缺城市先问、同会话“广州”执行`search_web`、新会话单独“广州”不继承外查、明确拒绝后两类外查均停止。所有回复保存，流式及最终文本均无DSML。
- 在用户原天气会话重新发“广州”：实际显示“搜索网络”约670ms，读取2/8；旧协议文本显示隔离说明，不改写历史数据。角色卡未重新编辑、搜索或填入新资料。

首轮实测仍发现模型把无地点问题改成全国天气搜索，随后补充语义topic及原话地点校验，重新跑通上述验证。测试账号旧登录令牌过期后使用既有凭据重新登录，未更改账号或密码。

## 实际限制

目前免费HTML搜索源返回的广州结果主要是百科与政务页面，未取得可核对的实时气温/降雨。修复的是联网续问、真实执行与协议输出链路，不宣称天气数据已可靠获取；回答明确未查到，没有编造天气。没有新增或自动执行`search_weather`，也没有把通用搜索改为专用天气供应商。

远端决策模型仍未连通，本轮实服务验证走已有降级路径；没有重训、推送GitHub或部署正式环境。私有原始SSE与截图保存在本会话`outputs/search-followup-20261018`。
