# 对话修改、目标收尾与反馈驱动的后续调整 · 2026-10-17

## 本轮行为

此前目标写入仅支持新建、步骤进展和完成后的续写，没有修改已有步骤或用户主动结束整个目标的操作。现在目标相关输入先经原4B模型门控，再由现有生成模型在有界候选中判断revise、complete、pause或不操作；其余创建/进展仍走原门控和写前核对。没有新训分类器，也没有把新操作当作旧4B已训练过的标签。

- “第二步你优化一下，来点详细的”：修改指定待做步骤并保存，保留ID、状态和原反馈；不只口头给建议。已完成/暂缓步骤不能经此操作改写。
- “整个目标我觉得已达成，标记完成”：尊重用户对整个目标的收尾，保存completed并停止自动追加，即使旧自动标准要求持续一周。其余未做步骤保留原状态，不伪造执行事实。
- “这个目标不想继续，先暂停”：保存paused，区别于成功达成目标；“今天休息”和“今天任务完成”仍属于当次步骤。
- 完成时补充“感觉太吃力/我实际做了……”不必另提修改请求：同一次规划可依据这些信息调整最多3个现有planned步骤，并说明依据，优先复用原步骤而非插入替代项后留下冲突旧任务。没有新依据时保留合适原计划。

## 保存与撤销

新增受控工具manage_goal，不加入只读自由选择列表。它接受账号原始回执、目标版本、操作和有限步骤补丁；应用签名绑定原话、账号/会话/请求、目标/版本、操作及补丁SHA。后端核对本人目标、当前active状态、planned步骤、重复标题和自动同步偏好。重复请求返回同一审计记录，目标版本变化时拒绝覆盖。

管理操作复用check-in账本和私有撤销快照，无新数据库列。步骤修改/整目标收尾可撤销，后续变化仍受版本保护。完成后的自动适配也随该次进展一并撤销，恢复原步骤和反馈。模型规划故障仍不丢已保存的完成事实。

修改/收尾的即时回复直接依据已保存回执，避免保存后又给另一个未保存方案、再次询问是否保存。下一轮读取保留上一轮写入定位的目标摘要，包括终态；完成状态不能因尚有planned历史或本轮未写入被否认。该焦点仍受账号、原回执和版本核对，不据此开放已结束目标的进展写入。

## 规划提示词

先看本次真实产出和所处阶段，再选择练习、应用、验证或巩固；有主题依据才具体化，不虚构掌握情况或感受，不把“明天再学一点、记录两句”当通用模板。不为新颖不断加码，习惯目标需要重复时允许继续并说明依据。用户做法已覆盖后续一部分时调整剩余行动，吃力时缩小范围，合适时再迁移应用；不擅自提高目标标准。
