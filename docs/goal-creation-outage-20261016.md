# 目标创建服务故障及错误原因传递 · 2026-10-16

## 实际原因

同一会话先说“设置一个每天睡够八小时的目标”，再说“帮我新建一个每天睡够八小时的目标”，两轮都已识别 creationRequested=true，并运行 begin_turn；但没有调用 create_goal。日志显示 GoalOperations.create 在调用独立 Qwen4B 目标 Executor 的 goal_creation 时遇到 httpx.ReadError。SSH 控制连接、Router、工具 Executor 和 Memory 仍在，服务器 18099 没有进程监听，因此不是用户表达不清或整条 SSH 断开。

旧目标 worker 日志以正常 shutdown 结束；现有证据不能确定是谁或什么触发了停止，不归因于训练效果、显存不足或提示词。

## 代码修改

- 保留目标模型授权和后端原始 receipt 校验，不在模型离线时绕过判断或借用工具模型创建。
- 创建流程传递有限的失败原因到实际 create_goal 结果：decision_unavailable、intent_unconfirmed、source_goal_not_found，以及后端返回的 plan_unavailable、invalid_plan 等。
- 故障回复直接按实际阶段说明服务或步骤生成不可用，不再统一要求用户“补充具体目标”。没有保存回执不声称创建成功。
- 请求指标增加 pipeline.goals.creationReason；保留未创建成功时已有的 partial 状态，并补上可区分阶段的原因。未改变权重或训练。

## 恢复方式

仅恢复缺失的目标 Executor worker，复用原基座、适配器和合同，绑定服务器回环18099；使用当时有余量的 GPU1，保留原服务20%进程显存上限。没有停止或改动其他任务。启动脚本、日志、PID和运行缓存全部放在服务器 data 盘。就绪以实际 health/鉴权调用和完整创建联调为准。
