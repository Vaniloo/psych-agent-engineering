## 评测顺序与判断

同一V2渲染器下先运行基座领域测试和72行冻结评测，然后训练候选，再在calibration上选独立适用性阈值。validation只验证既定门槛：选择准确率≥80%、误调用率≤5%、调用召回≥70%。test和72行冻结样本不调参。

额外实验检查预先固定为：冻结样本选择准确率≥80%、误调用率≤10%、调用召回≥80%；候选默认零阈值的选择准确率不得低于同输入下基座。原始与校准后的结果分别报告，避免用不同阈值掩盖退化。即使这些实验检查通过，也不会自动部署。

这是合成数据/教师草稿及助手编写评测，不是独立人工金标。72行只有24个逻辑题，多个表示是相关样本；成绩不能外推为线上可靠率。新数据每轮仅201个训练逻辑状态，主要验证生成器修复和训练方向是否有效。

calibration选出的margin阈值为1.75。它在校准集把误调用压到4.04%，同时调用召回仅26.75%；validation选择准确率50.11%、调用召回36.90%，门槛未通过。这不是成功的兜底：它将很多本应调用的请求转成finish。原始模型确有改善，但校准可分性和澄清判断均不足，不能以误调用率下降宣称可替换。

冻结24题中，零阈值三种表示全部正确16题、名称/顺序选择不稳定1题；校准后全部正确5题、不稳定5题。领域核心36组对照两端同时正确，基座5组、候选零阈值14组、校准后8组。

具体原始选择错误：嵌套字段缺失仍调用、历史中用户已经给出的嵌套条件却finish、助手/他人信息应澄清却finish、数组不满足minItems仍调用、成本反转仍选旧的较弱工具、失败状态带有貌似完整payload时误当作证据充分。改善集中于完整证据停止、空/零/false证据识别和概念请求；不能将来源绑定已经解决作为本轮结论。

实际训练402个状态、52次更新；优化9.0分钟，含基座与候选评测总耗时24.4分钟，峰值显存11.72 GiB。没有追加训练，没有根据冻结评测重选参数或阈值。数据实际每轮仅201个逻辑状态；覆盖或更新不足是待验证假设，不能据此断言4B容量上限。
