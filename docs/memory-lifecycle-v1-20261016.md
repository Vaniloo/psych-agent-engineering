# JEV式记忆生命周期：第一阶段 · 2026-10-16

本报告为第一阶段快照；当前候选与旁路策略的进展见 [第二轮报告](memory-lifecycle-v2-20261016.md)。

已在 `feat/jev-memory-lifecycle` 建立独立契约、带来源的条目账本、只读旁路和可复现训练课程，并完成一次4B LoRA续训。**本轮候选不替换正式 Memory**：新任务有提升，旧 relevance 有回退，且仍有错误接受。冻结标签 `freeze-20261015-memory-baseline`、原数据库和原模型权重保持可回查。

这保留了 JEV 的独立判别控制面：模型回答有界问题，程序结合判别、账号、来源、版本和预算决定建议；不是让生成模型直接自由改库，也不等于完整 Jev-Mem 复现。

## 第一版链路

```text
Java消息+事务outbox（权威原话）
  → 原Memory索引/分类/检索（正式链路保持）
  → 白名单只读旁路队列（容量64，满时丢预览，保留原话）
      → 来源句段候选（≤2条，完整输入≤2000字，每段≤400字）
      → 4B：write_worthy + grounded
      → 同账号条目候选（最近最多8条，BM25选最多3条比较）
      → 4B：duplicate + supersedes + conflict
      → 程序：skip / add / support / replace / keep_separate / review
      → 独立审计表（每账号最近200条；不调用apply，不参与正式召回）
```

新契约 `psych-memory-lifecycle-v1` 共12项任务，保留旧7项及其原始 renderer。正式服务继续使用 `psych-memory-v4`；两者请求契约不兼容时拒绝，避免误配新旧服务。

账本记录账号、来源request/session、原文区间与全文SHA、时间范围、版本、替代关系。`apply` 只用于离线约束验证，没有线上入口：默认拒绝写，显式测试启用后仍检查账号、乐观版本、幂等、临时事实不可覆盖稳定偏好、活跃预算。冲突未解决时返回保留分开，低置信度或互相矛盾的判别返回review。

## 训练与数据

基座为 `Qwen/Qwen3-Reranker-4B`，在10月12日的 Memory adapter 上继续一轮，而非从零训练。旧任务回放2882条+新任务3000条，共5882训练行；calibration 1832、validation 1852、test 1919。BF16 LoRA r16/alpha32、学习率3e-5、微批4×累积4，368次优化；峰值分配约8.51GiB。报告计时551.99秒包含训练循环后的校准/评测，未包含初始化与训练前对照。

新任务按120个事实族隔离划分，训练60族、其他各20族；相同的归一化任务输入和挑战输入不跨训练分区。旧课程保留原冻结分区。不同分区仍共享语义模板，且新课程标签主要由程序构造，不能视为独立人工金标、真实用户效果或临床验证。

新增任务模板test得到1000/1000，但它与下面开发挑战的差距明显，不能据此认为问题解决。完整参数、SHA、挑战和复现方式见 [训练产物](../agent-runtime/training/experiments/memory-lifecycle-20261015-v1/README.md)。没有使用真实用户聊天，也未再次调用教师API。

## 冻结开发挑战：训练前后

前后用同一原始 yes/no 分数规则；旧模型在新增任务上的结果是套用新指令后的对照，不代表它原来线上提供这些任务。训练前未重新校准接受策略，因此仅比较原始正确数；训练后错误接受/弃权按候选校准策略单独列出。

| 任务 | 样本 | 训练前正确 | 训练后正确 | 后错误接受 | 后弃权 |
| --- | ---: | ---: | ---: | ---: | ---: |
| relevance | 116 | 113 | 111 | 4 | 1 |
| evidence_sufficient | 70 | 70 | 70 | 0 | 0 |
| episodic | 23 | 18 | 20 | 2 | 1 |
| semantic | 30 | 29 | 29 | 1 | 0 |
| preference | 28 | 27 | 28 | 0 | 0 |
| procedural | 26 | 26 | 26 | 0 | 0 |
| temporal_need | 18 | 18 | 18 | 0 | 0 |
| write_worthy | 12 | 7 | 10 | 2 | 0 |
| grounded | 12 | 10 | 11 | 1 | 0 |
| duplicate | 12 | 10 | 11 | 1 | 0 |
| supersedes | 12 | 12 | 12 | 0 | 0 |
| conflict | 12 | 8 | 9 | 2 | 1 |

旧任务合计301/311→302/311，不能用总数的小幅提升掩盖relevance退化。新增任务47/60→53/60（78.3%→88.3%）；每项只有12条，不足以支持自动写入。

残留错误包括：把第三人称怕狗视为本人长期事实；漏掉预约从周二改周三的保留价值；把“今天不想喝咖啡”与稳定偏好视为冲突；把送围巾的施受关系颠倒仍判重复/冲突。拒绝长期记忆的原话还出现grounded误判，应用在模型之前直接跳过该类预览。这些是保留旁路、拒绝晋升的具体原因。

## 实服务旁路验证

候选端口18100使用独立权重SHA与12任务契约；正式18096仍加载10月12日的Memory。10月16日恢复SSH和缺失的自有worker，未重复训练、未覆盖原权重。冷启动期间服务未就绪，未把降级调用算作新模型通过。

直接通过候选HTTP服务运行8项合成旁路诊断，动作符合预期6/8，预置本人事实保持不变，正式记忆写入0。这里检查动作与来源/存储边界，不是大样本模型评测：

| 场景 | 实际建议 | 结果 |
| --- | --- | --- |
| 同一稳定偏好重复出现 | support | 符合 |
| 今天临时不想听轻音乐 | review | 原预期skip；价值判断弃权，未授权写入 |
| 明确更正稳定音乐偏好 | replace | 符合；仅建议，未实际替代 |
| 同一宠物出现未解释的新名字 | keep_separate | 符合；未覆盖旧名字 |
| 新增森林散步偏好 | keep_separate | 失败：与旧事实误判冲突，应可共存 |
| 查询兔子名字 | 不生成候选 | 符合 |
| 明确不要长期记住 | 不生成候选 | 符合；模型调用前跳过 |
| 今天有点高兴 | skip | 符合；仅跳过长期记忆建议，原话仍保留 |

首项含首次推理约3375ms，其余有模型调用的场景约59–154ms；查询/拒绝保留在本地跳过。这只是单条串行开发诊断，不能当作吞吐、P95或生产容量。完整概率、弃权与建议见 [旁路结果](../agent-runtime/training/experiments/memory-lifecycle-20261015-v1/shadow-results.json)。

随后通过5175前端代理，以一个新建的专用合成账号发送稳定散步偏好。实际生成回复、消息保存成功，事务outbox被消费，后台产生1条候选模型的add审计记录，活跃条目仍为0。正式Memory健康信息仍为旧模型。该验证没有直接调用ingest来替代消息/事务链路。

当前本机Runtime只对白名单内这一个合成账号启用旁路；真实账号不会新增这些预览。指标显示 `mode=shadow`、`formalWritesEnabled=false`、`processed=1`、`failed=0`，处理数只证明后台作业执行，不代表语义准确率。默认仓库配置仍关闭旁路。安全摘要见 [联调结果](../agent-runtime/training/experiments/memory-lifecycle-20261015-v1/live-integration-summary.json)。

## 已完成与后续边界

已完成独立契约、来源账本基础、受控动作约束、白名单后台预览、课程生成、单轮续训和逐任务回归。Router、工具/目标Executor、0.6B重排器未重训或替换。

本阶段使用完整来源句段，还没有生成式原子事实提取器；没有迁移旧原话索引，也没有把历史事实自动灌入旁路账本。因此新账本默认没有旧条目可比较，线上暂不具备自动去重整理收益。正式原话索引仍会增长，不能宣称已经节省存储。合成诊断预置事实仅用于检验建议链路。

自动归档、用户删除向派生数据传播、近期/长期联合读取、正式受控写入和等预算三组对照均未启用。后续优先针对错主体、施受关系、时间范围和明确更正做多样化人工审核边界集；先过旧relevance回归和写入错误门槛，再决定新一轮训练及小范围接入。
