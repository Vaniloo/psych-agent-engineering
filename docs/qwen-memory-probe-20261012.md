# Qwen Memory 候选实验 · 2026-10-12

已完成 Qwen3-Reranker 0.6B、4B 与正式 Memory v8 的同题对照。**本轮是预训练权重的离线试用，没有微调、训练、修改接受门槛、调用教师/回复生成 API 或切换正式模型。**

建议保留 0.6B 为后续“仅排序”的候选，不用未微调的 reranker 替换 Memory 的来源、相关性或充分性判断。4B 在这批输入上没有明显收益。该结果不能证明更大模型普遍无效，也不是本项目 scaling law 的拟合。

## 实验范围与冻结

- 106 条既有开发诊断：相关性 56、充分性 50。
- 新编写 80 条：24 个相关/不相关配对，共 48 条；与其中 6 个问题关联的 12 条来源变体；10 个充分/不足情景，共 20 条。充分性属于任务迁移探索。
- 全部 186 条及两套指令在首次 Qwen 推理前冻结。同一冻结文件用于两个 Qwen 模型及现有 Memory 的重新调用；未根据这批成绩选阈值、温度或重新写标签。
- 案例 SHA256：`72f0d072bfaaa597d6c463e57a0cc58716ee15fe16f9a69ba38a3899e9ea5b2b`。
- 指令 SHA256：`6e7b01a19da90f29bbbf697153d4cd3904676f48a4439340fcca14f3be48f901`。
- 新 80 条与所发现的现有 Memory split 文件做来源规范化精确审核：135,830 个候选/证据状态中，59,526 个因缺显式来源不能比较，可比较状态去重后为 18,309 个；新输入精确重合为零。不能据此宣称模板、语义或上游预训练独立。

全部标签是本项目编写的预期，没有独立人工或临床复核。配对、来源替换和证据变体相互关联；旧题已用于历史开发。这是开发实验，不是线上错误率、真实用户效果或独立盲测。

| 模型 | 实际参数量 | 固定版本 |
| --- | ---: | --- |
| Qwen3-Reranker-0.6B | 595,776,512 | `e61197ed45024b0ed8a2d74b80b4d909f1255473` |
| Qwen3-Reranker-4B | 4,021,784,576 | `22e683669bc0f0bd69640a1354a6d0aebcfeede5` |
| Memory v8 | 原正式模型与独立适配器 | 同题调用前后 health 中模型、权重/适配器摘要、契约和启用任务完全一致 |

依照 [Qwen 官方示例](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)，一次前向计算读取最终位置 yes/no 的 logits，不生成自由文本，也不调用聊天服务。Qwen 使用 BF16、SDPA、batch 4，串行运行在 GPU 0，最多使用该卡 30% 的进程显存预算，没有改变或停止其他服务。

同时保留两种指令：官方通用检索指令，以及冻结的英文 Memory 契约指令。后者显式要求核对 role、人物、事实与计划、否定和关系方向；充分性还要求全部字段及矛盾处理。role/content 用 JSON 保留，跟踪 ID 不输入；特殊模板定界符转义。输入不允许静默截断，超过 2048 tokens 会失败。

Qwen 的 yes/no 分数未经本项目校准，固定 0.5 仅用于原始标签比较，不代表 50% 正确率，也不移植 Laya 的 0.85 接受策略。所有候选 `deploymentEnabled=false`。Memory 的原始类别选择与“正确且接受”分开，下面使用原始类别选择，避免将 Qwen 不设弃权的覆盖与 Laya 校准覆盖混为一谈。

## 事实相关性与充分性

下表 Qwen 使用 Memory 契约指令：

| 评测项 | 正式 Memory v8 | Qwen 0.6B | Qwen 4B |
| --- | ---: | ---: | ---: |
| 新相关性配对：原始标签正确 | 32/48 | 28/48 | 30/48 |
| 新相关性：错误放过不相关记录 | 16/24 | 19/24 | 18/24 |
| 新来源变体：原始标签正确 | 12/12 | 0/12 | 0/12 |
| 旧相关性：原始标签正确 | 46/56 | 36/56 | 33/56 |
| 新充分性探索：原始标签正确 | 10/20 | 11/20 | 10/20 |
| 新充分性：不足证据误判充分 | 9/10 | 9/10 | 10/10 |
| 旧充分性：原始标签正确 | 42/50 | 21/50 | 21/50 |

来源变体包括 6 条 assistant 角色同文和 6 条 user 角色转述朋友内容。两个 Qwen 模型均将这 12 条判为相关。实际个人记忆初检已有 user 角色过滤，assistant 测试不等于生产泄漏；user 原话中的第三方归属依然不能由这项过滤解决。

两种 Qwen 都倾向放行主题相关文本。朋友养的兔子、别人给用户发的祝福等即使与问题贴近，也不能证明用户自己的事实；缺收件人、时长冲突等也容易被当成充分。高 yes/no 分数仍可能错误，不能直接作为事实可信度。

官方通用检索指令的相关性结果同样未超过 Laya：新增 48 条 0.6B 为 27/48、4B 为 28/48；旧 56 条分别为 32/56、30/56。两种指令都完整保留，不把较好的一种事后包装为唯一预定策略。

## 排序表现

在新 24 个问题中，每题仅提供一个相关记录和一个困难负例，比较相关记录的分数是否严格高于负例：

| 方法 | 相关记录严格排前 | 同分 |
| --- | ---: | ---: |
| BM25，相同两条候选与相同查询 | 21/24 | 0 |
| Memory v8 的接口 yes 分数 | 12/24 | 12 |
| Qwen 0.6B，通用检索指令 | 22/24 | 0 |
| Qwen 4B，通用检索指令 | 22/24 | 0 |
| Qwen 0.6B，Memory 契约指令 | 24/24 | 0 |
| Qwen 4B，Memory 契约指令 | 23/24 | 0 |

Laya 同分不是 12 次实际排错；稳定排序可能保留原候选顺序，且正式概率接口舍入/校准影响分数分辨率。这里使用的是记录分数的区分能力，不冒充纯语义能力对比。

排序有积极信号，但只有 24 个两候选配对。该测试未检验完整数据库初检、多候选池、全不相关输入、跨会话修正、矛盾证据保留或最终回复。**不是端到端记忆检索 Recall@k，也不能据此宣称问答成功率提升。**

## 成本与运行验证

| 项目 | Qwen 0.6B | Qwen 4B |
| --- | ---: | ---: |
| Memory 指令模式 batch 4 中位耗时 | 20.75 ms | 41.31 ms |
| 本实验进程峰值分配显存 | 1167 MiB | 7798 MiB |

计时包括分词、拷贝与推理，排除下载、加载和 warmup；两个模型实际输入长度不同，最后一个批次也可能不足四条。它不是每条 HTTP 延迟、生产吞吐、并发负载或 32K 长输入的显存估计。0.6B 此处具有更低成本且排序不差，故不建议本轮因参数量直接选 4B。

所有服务器模型缓存、脚本、冻结数据、结果和日志均位于 `/home/ubuntu/data/psych-agent-routing-20261009/` 下，复用 data 盘已有 Python 环境，未安装或替换依赖。两个一次性推理任务均自然完成。实验只读取合成案例和模型服务，未写用户对话、目标、进度或记忆；未改应用 Provider、权重、阈值和正式进程。

新增实验单元测试及既有 Memory 契约/适配器相关测试 14 项通过；新脚本 Ruff 和差异格式检查通过。没有以本实验重新跑整套 Python/Java/前端验收，也没有将测试通过当成模型效果证明。

## 下一阶段建议

保留 **BM25 初检 → Qwen 0.6B 候选重排 → 现有 Memory 来源/事实判断 → 证据不足时的轻量回复恢复** 作为待验证组合。先不部署，仅在相同的合成记忆库上继续检查多候选、全负例、修正/冲突证据与最终回答；重排不能丢掉关键反例或更正，也不能用一个分数阈值承担全部 Memory 职责。

如果继续优化，针对“本人事实/他人事实”和“全部字段/冲突”建立不同的监督任务，再考虑领域微调与独立校准。当前结果支持优先处理任务对齐，不支持直接扩到 8B 或替换三个角色。轻量兜底草案仍单独待讨论，本轮未接入。
