# 记忆生命周期第三阶段：候选与可撤销实验写入

本轮没有新训练。继续使用第二轮4B候选 `psych-memory-lifecycle-qwen4b-20261016-v2`，应用策略升级为 `memory-lifecycle-shadow-v3`。正式Memory仍为10月12日模型，正式检索没有切换到新账本。

已将只读预览延伸到**专用合成账号的独立实验账本**：可以实际新增、补来源、更正和撤销。普通账号不启用实验写入；业务消息和原话索引仍按原流程保存。

## 链路与模型分工

```text
Spring保存消息+事务outbox
  → 原话索引（正式检索保持原链路）
  → 白名单后台队列
      → 原文区间候选（最多2条，不生成改写）
      → 4B判断当前片段的保留价值
      → 4B依据完整消息核对来源
      → 明确属性边界排除不可能的目标
      → 4B判断重复 / 更正 / 冲突
      → 只读审计（来源、模型、策略、目标版本）
      → 第二层白名单：独立实验账本的受控写入
          → 原文证明+审计核对+账号+账本版本+目标版本
          → 变更日志；受影响条目未被后续修改时可以撤销
```

JEV/4B仍承担价值、来源和关系判断。程序只排除明确不兼容的属性、限制写入和维护事务，没有新增生成模型调用、模型权重或图数据库。

## 候选与属性边界

`memory_facts.py`只做提取式拆分。句子中的两个明确第一人称分句可以拆成两条原文区间，保留位置、全文SHA和会话/请求引用；更正语句保留完整上下文，避免把“不是……”裁掉。原文超过2000字或候选片段超过400字时保守跳过，原话仍保留。它不是通用原子事实提取器，不补齐隐含主体或改写事实。

例如“我平时喜欢听轻音乐，我今天有点开心”：保留价值分别对两个片段判断，不能因为整条消息有稳定偏好，就把当天情绪一起视为长期事实；来源核对仍看完整消息。未进长期实验条目的情绪继续通过近期原话读取。

第一版属性识别仅覆盖明确中文音乐偏好、本人宠物名称（带物种）、职业；多属性或不明确表述返回unknown。已知不同属性直接排除目标；属性相同也不等于重复或更正，仍需4B判别。未知属性的替代转复核；补来源需要属性已知相容或原文精确相同。没有用相似度直接授权写入。

这修复了开发用例中“音乐偏好的更正误命中宠物名字”。不宣称能识别全部人物、同类多只宠物或任意属性。事实族外、隐含指代和复杂更正仍可能漏提取或转review。

## 写入与撤销

- 默认关闭 `MEMORY_LIFECYCLE_SANDBOX_USERS`。启用时必须是显式shadow白名单的子集，拒绝`*`，拒绝实验账本与原话索引使用同一路径。
- `MemoryLifecycleShadow.inspect`仍只读，不调用apply。`MemoryProjection`重新由原始job构建片段，核对已经保存的审计、决策、目标与初始账本版本；缺失或篡改的计划不能写入。
- `add/support/replace`在独立SQLite事务中执行，校验账号和目标版本。新增不允许精确重复；同一消息中两个新候选若可能相关，后一个需重新规划，不能直接沿用空账本下的计划。
- 账本采用每账号单调版本。新增后撤销回空账本也会推进版本，旧计划不能利用状态回到原样重新提交；并发的同版本新增只允许一个提交。
- source引用和变更日志保留幂等依据。撤销保留记录并推进条目/账本版本，不把旧版本号重新启用；撤销后重放相同来源不会重新写入。
- 只撤销未被后续操作修改的受影响条目；不会一键回退整段复杂历史。撤销不是删除聊天，也不修改MySQL消息或原话索引。没有开放HTTP撤销接口。

账本包含`memory_items`、`memory_sources`、`memory_changes`、`memory_versions`和有上限的`memory_shadow`。变更日志只保存引用、版本和状态，不复制完整对话正文。旧实验source表会补充状态列；历史上没有变更日志的操作不会伪造撤销凭据。
