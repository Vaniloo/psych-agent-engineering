# 风险与目标保护修正、定向训练第九轮 · 2026-10-11

后续已完成 [第十轮训练与规则修正](training-contrast-round10.md)，下文保留第九轮当时的结果。

本轮完成 Router、Executor 的 2 epoch 定向训练与候选评测，**两个候选暂不接入**：总成绩提高，但都出现了新的关键接受错误。开发环境继续使用 Router v5 / Executor v6 / Memory v8。已测试的 Python/Java 风险与目标写入保护规则已接入本地服务；Memory 参数、契约与适配器未改动。

## 应用修正

- 风险扫描区分本人行动与明确的第三方、小说、翻译引用；本人认同引用中的危险意图仍保留识别。否认意图不能遮盖已服过量药、当前高处跳下、已准备遗书等行动信号。Python 与实际 Java 扫描共用回归案例。
- 风险分级在明确引用、低风险否认时校正模型判断，同时保留最近的本人风险与明确求助资源请求。不能据此宣称可识别所有表达或完成临床验证。
- 目标同步在 Python 候选层及 Java 最终写入入口检查本人、本轮证据、目标行动对象、否认与状态冲突。阻碍/休息不能自动写成完成；他人行动、回顾旧记录、错对象、未明确哪一步被拦截。所有权、版本、事务和幂等检查仍执行。
- 支持“写好了、放进去了、发出去了”等完成表达；过去已经创建目标的回顾不会再次调用创建。保护规则采用保守模式，混合主体或含糊表达可能需要手动同步。

这些规则是应用对自动行为的否决条件，不是新的 Laya，也不能把规则补足算作模型能力提升。

本轮在看到结果后采用保守的发布审查，**不是预注册门槛**：两组可用正确不能整体下降，不能新增关键任务的接受错误，不能错误自动写目标，接口、任务启用与数据精确隔离检查必须通过。结果：

- Router v6 新增一个接受的 urgent → elevated 错误（`guard-r9-003`）。旧版同样不够可靠，但会弃权；候选变成接受错误。规则虽能把该案例送入危机流程，不能因此忽略模型回退。另有 2 条原本可用的普通能力案例退步。
- Executor v7 在“我今天没写便签上的烦心事，两件都没写”新增接受的行动选择及 partial 错误（`readiness-0145`）；另一个错对象案例从弃权变成接受错误（`guard-r9-037`）。新规则拦住了这些写入，但模型未通过审查。另有 3 条原本可用的案例退步，其中同一实际完成表达的两种候选顺序都弃权。

服务端两个候选的 `deployment.json` 已标记 `promotionStatus=rejected`，权重保留供分析。仅停止本轮独立候选服务；正式三角色 worker 未替换，未改动其他进程。

## 应用验证与评测边界

在同一最终保护代码下重放旧模型和候选的记录，避免把规则变化混入模型对比：

- Router：旧模型和候选各 58 条已声明的分级检查均通过。它们检查流程分级，没有调用生成回复。
- Executor：两版各 113 条应用探针，均没有把预期不写入的目标负例变成候选写入；旧模型仍有 11 条有效进度漏同步/错误状态，候选 2 条。因此不能称目标链路全部正确。
- 150 项 Python 测试和 Ruff 检查通过。后端 15 个测试类、51 项测试通过，覆盖实际服务校验和 H2 目标事务/幂等/所有权等场景。
- 重启本项目本地 Runtime、Java 后端后，实际后端 20 条风险回归案例与 Python 一致；模型健康、Runtime、前端代理/Java 模型清单均核实为 v5/v6/v8，权重哈希不变。

没有发送聊天生成请求，没有修改用户目标/对话业务数据，没有做并发负载测试。自动目标否决条件仍是有限规则，对任意文本的语义正确性没有保证。

新表达在训练前冻结，未加入训练，但随后用于调试规则，所以不能当作规则层盲测。全部标签由项目编写，没有独立人工复核或临床标签。精确审核 36 个历史文件及本轮 8 个文件，比较 56,560 个历史规范输入和 10,738 个本轮规范输入，382 条评测精确重合为零；2042 个旧输入因来源字段不完整无法比较，也没有证明语义/模板独立。

初次候选评测传入的隔离审核复用了 48 条文件的记录并替换合并哈希，并未完整审核合并文件。本轮已在推理后、发布审查前重新完成合并文件真实审核；原始推理输出保留，`results-verified.json`、`summary-verified.json` 包含修正后的审核与来源说明，预测和标签未改动。
