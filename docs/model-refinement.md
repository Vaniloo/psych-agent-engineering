# 决策模型优化验收 · 2026-10-10

本文保留 v3/v4 的历史优化过程。最新线上为 Router v3、Executor v4、Memory v2；三个后续候选及拒绝上线原因见 [第五轮训练记录](training-round5.md)。

本轮已完成 Executor v3、Memory v3 和 Executor v4 的领域微调、校准、冻结诊断及真实开发服务联调。上线 **Executor domain-v4**；Router 与 Memory 保留 **domain-v2**。Executor 使用 lab GPU 0，Memory 使用 GPU 5，Router 仍为 CPU。三个角色各有独立权重，回复继续使用 DeepSeek Flash。

## 本轮解决的问题

之前的工具训练经常只有一个开放工具，而实际记忆问答同时开放读取目标等工具。新增带干扰项的权限掩码、查询类型、工具观察、充分结果结束、不可用工具和预算耗尽样本。

目标进展新增本人实际行动、部分行动、转述别人、仅想象、未来计划及助手引用的对照。第二轮训练使用更接近真实对话的平铺表述，避免依赖提示包装。最终 v4 从已有 Executor v2 微调，未沿用被拒绝的 v3。

先前 53 条诊断中，Executor v3 原始正确从 20/29 增至 24/29，却新增他人/想象进度误判，因此拒绝上线。Memory v3 原始正确从 17/24 到 18/24，但实际门槛下正确从 17/24 降至 10/24，并出现记忆写入分类回归，因此也拒绝上线。这批诊断帮助设计 v4，不能作为 v4 的独立测试。服务启动会在加载权重之前拒绝 `promotionStatus=rejected` 的检查点；重新冻结不会清除该标记。

上述都是小规模、作者编写的开发诊断，并非临床审核或真实对话质量基准。同一行动语义、近似模板仍跨划分存在；无完全相同状态交叉不代表消除了语义泄漏。

## 数据与训练

Executor v4：训练 1015 条，校准/验证/测试各 592 条，4 epoch，micro-batch 4。训练由 600 条旧训练回放、120 条工具转换、112 条新边界场景与 183 条教师草稿组成。DeepSeek Flash 生成 192 条虚构行动对照，9 条“部分完成”标签与句意不符的草稿被排除；其余仍明确标记为未经完整人工复核的教师草稿，只进入训练集。

训练报告中的 `experimental=false` 只反映留出标签满足当前流程要求，不能解释成临床验证。当前冻结元数据的 `trainingScope` 是旧有粗粒度字段；本段的逐项来源以及数据集清单是教师数据使用的准确口径。

Memory v3 完成 4 epoch，训练 1054 条、其余各 514 条；Executor v3 完成 4 epoch，训练 1308 条、其余各 768 条。失败或中止的早期尝试保留在数据盘，未作为最终模型。

全部权重、缓存、环境、数据、检查点与日志位于 `/home/ubuntu/data/psych-agent-routing-20261009`。最终模型分别位于 `models/psych-{router,executor,memory}-domain-{v2,v4,v2}`。

## 真实链路与速度

在隔离开发数据库中通过 Java → Agent Runtime → lab 三个 worker → DeepSeek → 实际保存验证：

- “只写了开头几个词，核心观点还没写完”正确保存为已有目标当前步骤的部分进展；随后撤销成功。
- 转述朋友、假设已经完成、明天才做三个对话均未保存目标进度。
- 记忆问答正确找回“一句话而非长清单”的偏好。第一轮由 Laya 直接选择检索记忆，结束判断低置信度时仍回退规则。原来同一问答约 15 秒，这次约 4.31 秒；这是单次真实观测，不是整体延迟基准。
- 同一份 v2 权重 CPU/GPU 对照，53 条预测完全一致。Memory worker P95 由 3.20 秒到 0.209 秒，Executor 由 1.046 秒到 0.183 秒。这个改善来自推理设备，不代表模型质量提升。
- 网页已确认显示 Executor domain-v4；旧慢请求保留，所以最近 7 天的混合 P95 仍为 15 秒。

## 复现与运维

新增 `training.refine_decisions`、`training.refine_executor_safety` 和 `training.evaluate_challenge`。先冻结诊断，再生成教师草稿、筛选并构建训练划分，使用已有 `training.train_decisions`、`training.freeze_deployment` 训练和校准。评测器调用实际鉴权 worker，计入服务校准与实际客户端门槛。生成教师数据需要私有 DeepSeek 环境变量；凭据不进入代码或训练结果。

lab 的 `src/three-laya-current/start-decision-services.sh` 按角色启动当前版本，默认三个角色，也可传 `executor` 或 `memory`。只有确认旧进程已退出、端口空闲后才重启；脚本会拒绝重复占用。服务仅监听 loopback，通过 SSH 转发连接本地开发服务，未配置操作系统开机自启。

本轮增加数据划分隔离、教师标签冲突过滤及拒绝检查点不能加载的测试。后续训练应继续补充真实改写的部分进展、记忆复合问题的证据充分性及用户/助手/第三方来源辨别，不以降低门槛替代改进。
