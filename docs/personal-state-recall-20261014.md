# 跨会话心情回顾修复 · 2026-10-14

用户在一个会话说“今天我有点高兴”，换会话询问今天的心情、连续追问“怎么样”，助手却表示没有信息。只读核对发现：原话已进入记忆索引，直接检索能够返回；主要问题是这些表达被路由为 chat，没有进入必需记忆读取，且对话超过两条用户消息后，薄上下文的自动背景召回不再触发。将记忆当作可选背景的回复约束也不适合回答事实回顾。

## 修复

- `personal_recall.py` 将“我今天心情怎么样”“今天我的情绪如何”“我今天过得怎么样”及短片段“我今天心情”识别为本人记录回顾；不会将“今天我很高兴”等直接陈述当成查询。
- 应用读取保障将这些请求转换为 memory 路线，强制执行 `memory_search`，不依赖 Router 输出 memory 或用户说“记得我”。Router 模型及全部接受阈值保持原样。
- “怎么样”“你看看最近对话”可以继承同一账号同一会话最近六条用户消息里的回顾对象；不从助手的旧否定回答推断事实，换话题后停止继承。
- 查询使用 lookup 用途，允许当前及其他本人会话；不再受薄会话背景读取的两条消息限制。拒绝读取、第三人称、引用和未来预测不触发这项保障。
- 仍使用原来的记忆工具和 Memory Qwen 模型。查询内补读最多 24 条已保存的本人用户原话，通过来源检查、重排和相关性判断，与索引候选合并。没有新增一个独立搜索 Agent，也不把数据库消息重复写入 SQLite。
- 新内部只读接口 `/internal/agent/recent-messages` 由服务 token 保护，按实际 owner 限定，排除助手文本，弥补消息已保存而 outbox 尚未处理的间隙。索引里的分类仍在后台进行。
- 原始记录与新消息去重后，重排池最多 32 条；相关性评分按每批最多 16 条分批发送，沿用 worker 接口上限。最终证据仍受原有返回数量限制。
- “今天”按 `MEMORY_QUERY_TIMEZONE`（默认 Asia/Shanghai）过滤。新业务来源和 outbox 带时区，历史无时区记录按 `MEMORY_LEGACY_TIMEZONE`（当前开发环境 UTC）解释；同天记录但仅叙述昨天/明天的内容不能作为今天经历。
- 相关证据先按记录时间排序，再限制返回数量；回复端使用来源日期及 recencyRank，避免旧情绪压过最新陈述。未询问具体时刻时不给模型小时字段。记录日期不等于事件日期，引用只证明当时表达，不判断全天或当前一直如此。
- 明确查询时清除过期助手否定回答的影响，直接概括已检索原话；controlled 状态仍可回答有证据的部分，空结果只能说明本轮没找到。

## 验证

Python **513 项通过**，含新增 21 项个人回顾、同义表达、短追问、跨日时区、来源去重、后台索引尚空、16 条评分上限及旧助手回复排除检查。Java **66 项：65 通过、1 项原有跳过**；数据库集成核对近期来源只读、仅本人用户文本、最多 24 条以及 outbox 仍待处理时能读取。Ruff、差异与原有前端工具活动检查通过。

专用合成账号八轮完整复测保存成功：另一个会话表达高兴、新会话直接查询、三种追问、另一会话更新为累、读取最新变化、明确拒绝检索。没有创建或同步目标。额外两轮核对最终日期展示与连续追问。真实报告账号仅做只读检索和独立回复验证，匹配原话来源，未创建消息或改动目标。

记录在会话 `outputs/mood-recall-20261014/`。未重新训练、修改权重、改变阈值或执行容量压测。这是应用路由与检索衔接修复，不是模型泛化能力提升；更复杂同义表达和跨日期事件仍需持续评测。
