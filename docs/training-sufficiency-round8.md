**已完成：Router v5 / Executor v6 / Memory v8 正式接入，应用端版本核对通过。** 本轮只训练 Memory 的 `evidence_sufficient`，沿用上轮已改善的相关性参数和原五项分类/时间需求参数。全程在 lab data 盘训练，未使用教师或生成 API；未增加第四个 Laya 角色。

## 问题与修正

上轮 90 条公开改编记忆诊断中的 24 条接受错误均来自充分性：16 条将助手同文误当成用户证据，8 条漏判完整用户证据。模型虽会区分部分来源，但稳定性不足。

新增 `psych-memory-v4` 契约。整体充分性输入规范为 `query` 加至多八条 `evidence={role,content}`，必须显式声明来源，缺失角色被拒绝；业务 ID、session、source 与观察时间由应用保留，模型不接收追溯字段。观察时间不被当作事件发生时间；需要时间的事实仍应来自原文。

充分性问题明确检查用户来源、全部字段、证据合并、本人否定、缺失与无法消解的矛盾。它与逐条相关性分别调用，不允许在一次请求中混入其他任务。v2、v3 契约及原问题保持兼容。Runtime 和逐轮运行指标使用配置中的 Memory 契约，修正先前遥测固定写 v2 的问题。

Memory v8 包含三个参数来源，均属于同一 Memory worker：

| 任务 | 参数与校准来源 |
| --- | --- |
| episodic / preference / procedural / semantic / temporal_need | 原 Memory v2，字节不变 |
| relevance | 原 Memory v7 的完整相关性适配器，字节不变 |
| evidence_sufficient | 本轮独立训练的完整参数与新校准 |

每次适配器调用结束或异常后恢复原参数；请求及参数切换均串行保护。两个适配器包含 encoder 和 head 的完整参数，**不是 LoRA，也不是仅训练 head**。缓存完整参数会增加显存占用，不能按小型 LoRA 的资源开销估算。

## 冻结实际服务验收

使用上轮相同文件哈希、案例与预期；只适配版本化输入，不改标签。可用正确要求整条状态所有任务正确且被接受；接受错误表示被接受但存在错误任务。

| 第三轮中文 | 24 | 17 | 19 | 7 | 5 |

192 个未改变任务的预测、概率和阈值逐例一致，最大概率差为 0。30 条相关性可用正确仍为 29，未重新训练。中文组剩余错误来自原分类任务：第五轮 preference 1 条，第三轮五条状态涉及 semantic / procedural；它们没有因本轮训练回归。

公开改编组的四条接受错误均是对 expected=yes 完整证据输出 no，仍有漏判；该组助手克隆不再出现被接受的错误。不能将“24 → 4”描述为完全解决充分性，也不能把短证据改编评测当作原始长程 QA 成绩。

14 个业务表示探针预测均正确，12 个达到应用接受门槛；两个矛盾证据探针保守弃权，未被判为充分。关键完整与合并证据均正确且被接受；加入追溯字段前后概率完全相同。接入门槛明确允许负例保守弃权，不降低 0.85 下限来追求覆盖。

临时 worker 通过门槛后只替换已有 Memory 进程。正式 worker 再次执行所有冻结组，预测与接受决策逐例一致；校验原基础、原相关性、新充分性三个哈希。Router、Executor 进程未更换。

实际 MemoryService 使用独立合成 SQLite 索引，6/6 检查通过：用户和助手观察写入、本人事实筛选、朋友/助手排除、来源 ID/时间保留、两轮上限、用户隔离及缺失次数/时长不判充分。完整事实返回 sufficient，缺字段继续收集而不虚构答案。这里不是再次调用生成模型的整段对话验收。

Runtime、Java 和前端代理的实际模型清单确认 v5 / v6 / v8，Memory 契约 v4、新适配器哈希正确，7/7 检查通过。本地 SSH 转发已恢复。

正式服务少量串行整状态延迟：中文 9 条 p50 97.40ms / p95 797.32ms；中文 24 条 p50 24.51ms / p95 209.91ms；公开改编 90 条 p50 24.96ms / p95 54.60ms。包含参数切换；不是并发吞吐基准。
