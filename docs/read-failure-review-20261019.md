历史记录缺少完整的当轮工具轨迹，不能仅凭一句“没有记录”断言当时一定没调用工具。当前8个可复放用例均进入记忆读取，说明这批残余问题主要集中在候选、筛选与交付覆盖。宽泛问题在错误chat路由或已建立会话下的必读保障另有单元回归。

另保留4个对照：明确准备考试后的活动回顾、近期TCP学习回顾、未提供生日、只表达开心却未说明原因。生日和开心原因的历史拒答有依据，不能标成失败；助手给出的学习清单也不能充当用户已经做过的事实。

## 本次修复

1. `personal_recall.py`补齐宽泛的本人了解、其他会话回顾，以及“我最近怎么了”的问句语义。这些明确读取使用同一记忆工具、同一账号范围与近期原话桥，不再取决于会话是否刚创建。同时将这些纯提问排除在答案候选之外，减少旧问题占据召回/复核名额。
2. 宽泛回顾已有少量接纳证据但仍不充分时，可把另外最多2条符合现有来源保护的原话交给最终回复核对。它们仍单独放在`candidateEvidence`，不提高模型置信度、不改成已接纳证据；背景检索不启用这项补充，没有新增模型调用。
3. 补齐读取诊断：记录授权/必读工具、实际动作、候选来源ID、接纳/待核数量，以及最终回复上下文裁剪前后的证据数量。由此区分入口未读、检索不可用、没有接纳、部分覆盖与上下文缩减；诊断信号统一标记`待复核`，不会把正确拒答自动标错。

没有重新训练或修改权重，没有追加关键词直接判定某条记忆为真；新增口语识别属于现有只读保障，相关性仍由独立记忆模型判断，待核原话仍需回复阶段逐条验证。

## 后续积累方式

每轮指标包含`pipeline.readAudit`。有疑点时，派生SQLite索引的`read_audits`记录同账号/requestId的诊断元数据，不另存一份对话正文；保留14天、每账号最多200条，同账号清除记忆时一起清除。记录失败不会影响对话结果。

可用`python -m benchmarks.collect_read_failures --database <本机索引> --owner <指定账号> --out <仓库外私有目录>`导出候选。默认不导出原话；显式加`--include-dialogue`才以同账号、精确requestId关联现有原话，不能按相邻时间串联其他会话。导出文件0600，条目初始为`unreviewed`、`trainingEligible=false`。后续结合用户反馈和原始来源逐例确认，不能直接变成训练标签或自动报告失败率。
