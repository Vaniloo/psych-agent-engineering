# 跨会话上下文补充 · 2026-10-13

已接入本地开发 Runtime。复用同一个 memory_search 工具、原话索引、0.6B 重排、微调4B相关性筛选，没有增加生成模型规划器或训练新权重。

本文是10月13日实现记录；10月15日已补充事实查询保障、候选过滤、近期原话桥接及自然引用表达，见 [当前修复说明](cross-session-recall-fix-20261015.md)。下文固定“你之前提到过”的旧规则已取消，时间、冲突或用户问来源时再说明依据。

## 触发与范围

- 新对话或当前会话最多2条用户消息时，可补充背景；已有较多上下文时，只有“上次/那件事/继续”等延续表达才触发。
- 仅同一账号其他会话的用户原话；SQL在候选排序前排除当前会话，避免当前提问占据召回名额。助手建议不作为用户事实。
- 先做轻量检查：没有其他会话的索引记录就不调用模型。后台异步入库尚未完成时，下一轮才可能查到。
- 保留现有候选范围：最近最多2000条用户原话的BM25候选、最多24条近期原话参与重排扩展，不遍历或总结完整历史。
- 最多交付3条相关原话，仍遵守每轮最多2次读取。既有两项工具已占满预算、明确危机/专业支持路径、目标写入、明确个人记忆查询时，不另加自动背景读取。
- 明确不查历史、只聊当前、重新开始、问候、公共定义及引用示例不触发。已经开放的显式记忆读取保持原有行为。

## 使用与降级

同一工具用 purpose=context 标识背景用途；session_id由Runtime注入，MCP与本地工具使用同一参数契约。保留当前会话，用户最新陈述优先；使用过去事实时提示“你之前提到过”，不推断旧经历仍在发生。无结果就正常聊天，不宣称用户从没说过。筛选模型故障时不注入未经核实的词法候选。

放松场景使用“我喜欢怎么休息和放松？”查找所需背景，避免“今天/简短回应”让重复进度消息淹没偏好。其他场景沿用当前输入，去除末尾篇幅要求。没有新增独立检索流程或放宽4B接受门槛。

前端沿用记忆工具卡片，显示“补充N条其他会话的相关原话”；运行接口返回crossSessionContext开关、检索purpose/scope。配置 MEMORY_CONTEXT_RECALL_ENABLED=false 可关闭自动补充，显式查记忆仍可使用。旧画像/摘要字段面板未在本次改动中重构。

## 验证

- 完整Python测试392通过，包含19项新增检查：触发与拒绝、已有上下文、共享工具预算、候选前排除当前会话、同账号隔离、模型故障不注入、保留本轮上下文、避免重复进度淹没偏好。
- 6个冻结合成模型联调场景：放松2条相关证据、面试延续1条证据、当前拒绝听音乐时遵从本轮说法、无关历史不带入、不查历史不调用、仅当前会话时不调用。实际0.6B/4B/DeepSeek，临时索引，没有业务写入。
- 实际前端代理→Java→Runtime的3条专用账号新会话请求全部保存：背景检索补充2条原话；随后不查历史、公共定义均未读取记忆。工具活动摘要及purpose/scope已确认。
- 首次HTTP验证揭示重复进度抢占候选，采用查询适配后重新验证；服务切换时有一次冷启动失败，最终健康检查后重测通过，不计入正常结果。最终结果位于会话outputs/context-recall-20261013/http-smoke.json与worker-ready/worker-replies.jsonl。
