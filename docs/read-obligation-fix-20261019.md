# 读取衔接修复（2026-10-19）

记忆模型独立于 Executor，但调用链仍是：准备工具权限 → Executor/loop 发起 `memory_search` → MemoryService 候选召回、0.6B 重排、4B 相关性与充分性判断 → 回复生成。上游没开放或调用记忆工具，下游模型不会执行。新 ToolACE 4B 候选尚未替换正式 Executor，上一轮候选的原始漏选不能解释成线上记忆权重被改坏。

## 本次代码修复

- 在现有个人回顾识别中组合独立问句，支持历史偏好表述。“看报告、看已完成目标，并回顾我以前喜欢听什么”现在会进入三项必读列表，再由既有 loop 执行完毕。记忆查询优先使用个人回顾分句，保留账号范围、跨会话原话桥与时间窗口；共享主语的多个问题不丢失后半项。
- 明确索要心理应对方法同样作为必读知识请求。例如“给我一点压力应对方法”，即使模型选 chat 路由或提前选择文字回复，也先查询知识库。倾听偏好、明确不查询、引用与示例继续受原保护限制。
- 不更换权重，不增加另一个生成模型。这里是现有规则保障的组合修复，不宣称新训练出了通用语义门控。原始候选工具选择分数不变；“梯度下降”额外搜索按用户意见降为低优先级成本问题。

实现位于 `personal_recall.py`、`route_policy.py`，新增回归在 `tests/test_read_obligations.py`。目标写入、风险判断与数据库写入权限不在本次改动范围内。
