## 测试范围与主结果

从现有`benchmarks/chat_quality.py`、浏览器反馈和已有回归中抽取22个开发用例。使用真实MCP函数docstring和`CAPABILITIES`参数schema，身份、session及签名等由服务器绑定的字段不作为用户需填参数。每题以原序和反序工具列表各测一次，比较同一4B基座与新adapter。

6个项目读取工具为`search_knowledge`、`memory_search`、`get_goal_context`、`get_dashboard`、`get_support_resources`、`search_web`。对完整train课程13,665个规范化工具名做核对，这6个名字都未出现；这只证明名称不同，不意味着语义工具家族全新。

## 暴露的问题

1. **个人记忆漏选。** “我最近经常吃什么”两种顺序都转交文字回复；“我今天心情怎么样”会选心理知识检索或文字回复。实际graph依靠既有必读策略调用记忆，此成功不能归功于新模型。
2. **稳定知识误联网。** “什么是梯度下降”两种顺序都选择`search_web`。公开示范选择学习尚未可靠迁移到项目对联网必要性的约束。
3. **可选知识检索提前退出。** “给我一点压力应对方法”在固定knowledge路由下，候选直接结束读取，没有调用项目预期的`search_knowledge`。基座调用了知识库，但也额外查询了记忆，说明两者都有需审查的取舍。
4. **复合读取权限遗漏。** “请查看我的心理报告、我完成的目标，并回顾我以前喜欢听什么。”只开放/执行了报告和目标读取，记忆未进入必读列表。两种模型都失败，且这一步没有模型评分调用，属于权限准备/意图拆分问题，不能靠换Executor解决。
5. **接口语义并不相同。** 新模型的`assistant_text`在隔离桥中仅映射为结束当前读取子循环、转交ResponseComposer，不解释为整个目标完成，也不伪装成已训练的clarify分类。正式控制器仍使用旧固定选项契约；本轮不是可直接上线的协议替换。

额外在6个失败后选出的用例上，将项目已有`TOOL_CHOICES`中文描述附加到MCP描述做开发诊断。天气顺序问题改善，个人记忆和稳定知识误联网没有解决；该诊断不计入主评分，也没有据此改动训练或正式提示词。

## 真实graph与实际读取

12个调度场景使用真实`AgentGraphRuntime`、`ToolController`、参数/结果校验、工具观察和响应准备节点；替换部分仅为隔离评分适配层。路由和目标创建判定使用固定fixture，回复使用明确标记的生成器fixture，落库由隔离回执代替。检查普通聊天、知识、跨会话记忆请求、已完成目标、报告、记忆opt-out、复合读取、网页搜索、目标创建顺序及读取失败。未观察到不属于当前绑定账号的调用参数或额外目标写入调用；这不等于完成了跨账号攻防或临床验证。

随后增加4个真实读取graph：使用既有专用capacity测试账号，启动临时本地MCP桥，连接现有Java后端、MemoryService和知识索引，不使用工具返回fixture。持久化仍被拦截，路由/回复生成仍固定。

| 真实读取 | 结果 |

| 记忆 | 成功，返回6条真实索引证据 |
| 心理知识库 | 成功，返回6条检索片段 |
| 目标 | 成功，通过真实类型校验 |

4个graph共12次真实MCP调用，包含4次风险扫描、4次上下文读取、各1次上述读取。未调用业务写接口，不评价真实回复文风或事实完整性，也未进行并发容量测试。

当前开发环境实际配置`TOOL_TRANSPORT=local`，默认MCP端点并非已部署的本项目服务。本轮临时桥使用独立18120端口，没有切换正式服务。还核对出本地MCP SDK 1.28.1的新`streamable_http_client`不接收`headers`参数，而项目现有可选MCP客户端仍这样调用；本轮测试使用带认证的`httpx.AsyncClient`传入`http_client`完成协议验证。正式客户端未修改，未来切换MCP传输前应修正这一兼容点。初次探测错误与最终成功结果分别保留。
