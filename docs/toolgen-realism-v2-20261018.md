# 工具决策数据 V2：消除格式捷径的小批量验证

本轮只修改训练数据生产和验收流程，没有训练新权重、没有替换当前 Executor，也没有给应用新增关键词门控。上一轮模型和原始实验报告保留。

## 修正内容

原来的充分证据状态统一带 `simulated` 标记、输出字段统一用 `field_0/1/2`，缺参问法几乎都显式提醒缺参数。V2 将是否虚构等来源信息只保存在元数据中，结果正文不再携带旧模拟标记，来源信息不进入模型输入。

- 工具契约使用有语义的输入/输出键、字段描述与 JSON Schema，返回普通字符串、数值、布尔和数组。
- 当前问法不主动提示缺参；同一句话补上适用的用户历史后可调用，只把同样的历史改成助手发言或他人的情况则不能冒充本次用户输入。
- 所需信息保持不变，改变可用工具集或成本，验证无工具→有工具、弱工具→强工具和简单请求的成本选择。
- 相同请求配完整、部分、空、null、失败、对象不匹配、无关和多片段结果。成功状态不代表充分，之前失败也不抹掉之后的充分成功结果。
- 0、false、空列表在对应契约下可以是有效事实；不能用真假值测试把它们当缺失。本 pilot 将 null 明确定义为字段不可用，其他接口若有不同含义需单独声明。
- 普通 `result`、MCP JSON 文本、`data` 三种包装均同时覆盖应调用和应停止；工具别名、候选顺序、schema属性/required顺序变化不改变语义标签。
- 模型输入排除 oracle、真实标签、来源审核状态；要求逐项可定位的参数证据和 typed JSON 结果校验。V1 训练入口拒绝 V2 contract，防止忽略 history 后仍使用其标签。

所有示例均为自建的虚构记录，不是线上用户记录，也没有执行真实查询。返回形式更接近普通 API，不代表数据是真实世界观测。

## 生产与审核

```mermaid
flowchart LR
  A[显式参数与信息需求] --> B[DeepSeek生成自然问法]
  B --> C[盲审需求与值的原话来源]
  C --> D[校验类型和引用位置]
  D --> E[构造并验证结果与工具集反事实]
  E --> F[隔离分歧和规范化去重]
  F --> G[冻结小样本，禁止直接训练]
```

试跑首先尝试让教师直接给出动作和所有有用工具。批量总工具表会导致跨案例选错候选；逐例处理后，教师仍易把“有用”理解成“唯一最佳”，并忽略部分上下文来源。因此不把这类动作判断直接当金标。

当前流程让教师独立提取用户实际请求的信息和各输入值的来源，不提供参考参数或期望动作。程序根据实际 role、引用位置、参数类型、schema、结果字段及查询对象作可执行验证，然后从已声明能力生成模式、适用性和排序标签。这是受控合成环境中的银标，仍需要审查，不能称为人工金标或任意真实 MCP 接口的正确性证明。

还修复了“第一项信息”依赖 JSON 对象排序的歧义：生成任务现在明确传递 `simpleInformation`。同样问法允许表达相同意图，不把它们当独立样本；相同模型输入若有相反标签则直接拒绝。

并发生产会合并完全相同的在途请求；一个任务失败时先等待同批其他请求完成，再关闭客户端。之前一个运单来源的结果不明请求未重发，该来源明确排除在本次验收外。缓存、原始失败实验和源码快照都保留，鉴权、额度和传输结果不明时不盲目重试。

## 实际小样本结果

- 七个工具家族，63 个源情景（含历史来源差异）的语义审核：61 个一致，2 个分歧。
- 原始派生记录 1,638 条。分歧对应 27 条派生记录全部隔离，再去重 27 条规范化重复输入，冻结保留 **1,584 条**。
- 63 对核心反事实完整保留；覆盖自然缺参、角色来源、真实形态的完整/不完整结果以及工具/成本变化。
- 两处分歧分别是：“另外不知道谁提交”可能暗含额外需求；泛指社区场馆的问法可能是在了解概念。保留原标注与分歧，不偷偷改成预期标签。
- 原始 pilot 的严格全通过标志为 false，仍保留。剔除上述分歧后的子集通过来源、结构、成对完整性和去重验证，但 `trainingReady=false`、`trainingAllowed=false`，不会因此直接进入训练。
- 离线重放新增 API 调用为 0，派生记录字节哈希与原试跑一致。模型输入未发现上一轮模拟标记或通用 `field_N` 字段。

这不是模型准确率。当前没有重新测量/训练 V2 模型，也不能与上一轮99.7%的模型选择准确率比较。旧的动作审核与新的源语义审核任务不同，其一致率也不能直接比较。

累计生产实验 ledger 记录342次API尝试、供应商报告输入359,899 tokens、输出34,111 tokens，包含废弃审核方案；有3次结果不明请求，用量不完整，不能据此计算完整计费。缓存复制/离线重放没有再次支付这些调用。

## 源码和使用

当前入口是 `agent-runtime/training/toolgen_v2/pilot.py`，转至 `ground_pilot.py`。`seeds.py`声明虚构契约，`core.py`构造成对状态与内容覆盖证明，`ground_review.py`校验盲审来源，`render.py`提供独立V2上下文格式，`curate.py`冻结同意子集并保留分歧。已废弃的动作审核源码保存在本会话输出的实验快照，不作为当前入口。

从 `agent-runtime` 运行，密钥只通过私有环境变量配置：

```bash
# 新目录、小规模生产；不会训练或调用真实工具
python -m training.toolgen_v2.pilot --out /absolute/pilot --max-calls 120
# 在源码与计划不变时，仅使用已有缓存；缺缓存就停止
python -m training.toolgen_v2.pilot --out /absolute/pilot --max-calls 120 --replay-only
# 冻结同意子集；若核心反事实被破坏或目标已存在则拒绝
python -m training.toolgen_v2.curate --source /absolute/pilot --destination /absolute/curated
```

本次使用缓存的旧问法，只重写明确有问题的 `simple/partial`，通过 `--base-generations`记录父版本。新生产不需要这一选项。源码/计划变化需新目录；旧计划和源码快照可独立复现。

当前实际验收工具以两项必需输入为主；单项和三项必需输入通过结构单元测试，仍需增加这类真实生产样本，扩充嵌套、可选输入和真实接口来源，并保留新的独立评测。少量虚构只读契约、同一教师的相关偏差和非人工标注都是当前范围限制。下一次大规模训练之前应先补足这些覆盖，而非直接放大本 pilot 的数量。

最终程序检查：814项通过、1项因本机缺少Torch跳过。使用本地已发布Qwen 4B适配器的tokenizer.json低层编码审计7,497个候选输入，最长1,385 tokens，无截断；这不是模型推理，正式训练前仍需完整AutoTokenizer接口核对。最终样本包为本会话outputs/toolgen-realism-v2-20261018/curated-final，验证摘要为verification.json。
