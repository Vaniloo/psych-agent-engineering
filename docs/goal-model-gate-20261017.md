## 改造范围

旧链路先用表达规则筛选，再让 Executor 匹配行动，后端又用文字规则验证；因此模型即使理解了省略表达，也可能根本进不了检查流程，或最后被另一层规则否决。“OK，小步骤1我做完了”就是这类问题。

新增独立 `psych-goal-gate-v1`，沿用记忆生命周期的本地 Qwen4B + LoRA 二分类评分方式，输入当前原话、最近四条对话和实际拥有的目标步骤。原话不再改写成规范命令后才让模型判断。语义判断包括目标相关、当前创建授权、本人实际进展、唯一行动匹配及 done / partial / blocked / rest。行动 ID、账号、版本均由应用从数据库候选映射，模型不能生成。

流程为：三项意图评分 → 创建，或读取，或逐候选匹配 → 四项结果评分 → 写前语义核对 → 原始消息落库 → 业务更新 → 以实际回执回复并发出原有 SSE。创建后的步骤规划仍用生成模型。一个步骤完成不会自动证明整个持续性目标完成。

首轮4B泛化测试暴露误写，**目前不让4B单独授权写入**。只在准备创建/更新时复用现有生成模型做一次JSON核对：当前完整原话是否授权、步骤是否唯一、结果是否准确。4B已有明确选择时必须一致，不能由核对模型另选。4B已经确认本人进度意图、但步骤/结果匹配失败时，允许核对模型从有限候选补判；必须返回现有零基candidateIndex、四种结果之一及当前原话片段。没有唯一依据则澄清，其他不授权场景拒绝，不新增词语匹配。

## 模式和边界

- `off`：保留旧链路，作为回滚基线。
- `shadow`：指定账号旁路打分，不改变原计划或授予写入权限。
- `model`：指定账号采用模型结果；语义不再经过旧的 `eligible_report`、`allow_creation` 和后端动作关键词检查。默认关闭，不能使用 `*` 白名单。
- 第一层意图拒判/不可用、写前核对不可用或没有唯一明确步骤时不写入，不偷偷回落到关键词授权。普通聊天和不写入的读取不调用核对模型。
- 后端仍验证账号归属、当前原始 receipt、完整 quote、目标/行动存在及状态、乐观版本、自动同步开关、幂等和撤销。不是取消业务约束。
- 模型模式使用五分钟有效、绑定账号/会话/requestId/原话 SHA/目标/行动/版本/结果的 HMAC 凭证；后端还固定模型权重 SHA。凭证不进入提示词、SSE 或公开指标。
- 第一版最多八个活跃行动候选；超过预算不自动更新。相邻轮次的真实创建/更新回执标记焦点，但不排除其他目标。它不支持一次消息同时更新多个步骤。

`GOAL_GATE_MODE/USERS/BASE_URL/API_KEY/TIMEOUT_SECONDS/EXPECTED_SHA` 由 Runtime 使用；后端必须配置相同的 `GOAL_GATE_EXPECTED_SHA` 和内部服务密钥。模型 worker 使用 `QWEN_GOAL_API_KEY`。Compose 已传递这些配置，但本轮没有部署 Compose 全栈。

## 训练和评估方法

独立候选从已有 Executor4B LoRA 继续一轮微调，不覆盖正式权重。基座为 Qwen3-Reranker-4B，BF16 LoRA r16/alpha32，学习率 1e-4，batch4、累积4，种子1412。服务继续使用 yes/no 评分，不自由生成工具参数。

课程由 `training.goal_gate_data` 可复现生成：训练5,504条，calibration/validation/test各4,128条，按主题与步骤变体组合隔离。模板共享，标签为程序编写的开发标签，不能将这些留出分数当作真实用户泛化准确率。另有29个冻结开发场景（250项决策），不用于梯度或阈值选择；此外用31条新的口语场景测试实际 HTTP 组合门控。

校准、原始 logit 稳定性门槛和调用端最低置信度保持分开；最终评价应统计组合后的误写/漏写，不只统计每个 yes/no 的准确率。`training.evaluate_goal_gate` 使用与实际服务一致的接受条件复放冻结决策。

同模板test集4,128项决策全对，但额外场景里引用、回顾旧记录和无唯一指代仍被4B误判为完成，说明其泛化与校准存在局限，不能以模板准确率宣布可单独上线。最终保留小模型的意图/权限入口，复用现有生成模型核对低频写操作，不继续堆关键词或重跑大规模训练。普通读取与聊天不增加该生成调用。

最终60场景通过同一实际HTTP模型链路验证，22项期望写入均匹配正确目标步骤和结果，38项不写场景未发生误写；5项使用有限候选补判。写入门控中位约1.32秒、最大约1.56秒；不写入门控中位约0.19秒。这些只包括门控处理，不能当作完整聊天响应延迟或并发容量。

这些都是开发者编写并用于迭代的场景；第二次完整复测明确了候选数组下标与小步骤序号的区别，因此不能再把该31场景称为完全独立评测，也不推断真实用户零误写。第一版误写、部分进度漏识别、核对后的漏识别及最终结果分别留档。梯度训练约1,076秒，训练与原生评估总计约1,780秒；继承报告字段trainingSeconds包含评估，不仅是梯度时间。
