# 心理支持对话的知识读取 · 2026-10-14

页面复现“我最近特别焦虑”只查记忆，“我感觉我心理特别焦虑”只查支持资源。知识库与 `search_knowledge` 工具均正常，问题在权限与工具流程：chat路线默认没有知识权限，professional_support优先开放/执行资源查询，Executor又可能在完成该工具后结束。

`get_support_resources` 返回联系方式和支持渠道；`search_knowledge` 返回心理科普片段与来源，二者用途不同。本轮将当前明确困扰与知识读取连接，而不依赖模型先选中knowledge路线。

## 当前行为

- 对本人当前焦虑、压力、睡眠、低落等明确困扰，在风险判断后补充一次必需的知识读取。使用一般主题查询，最多3条片段；不把用户的当前情绪当成诊断，也不修改风险标签或权重。
- ordinary/self_help可组合知识与近期记忆；professional_support保持资源读取优先，通常为资源+知识。既有明确事实读取占满预算时延后知识，不超过两次工具调用。
- 仍以陪伴为主，知识是背景依据，不强迫讲课或建议。当前困扰被误路由成记忆/科普时保留授权读取，但纠正回复用途；相关记忆作为背景原话，当前表达优先。
- 明确只想倾诉、不要建议或拒绝资料查询时不增加知识检索；最近用户的倾诉偏好延续，直到明确请求方法/知识。拒绝建议但明确询问概念仍可查询知识。
- 危机路径不变，第三方引用、否定当前症状、纯历史事实、目标/报告读取不被本策略强行改写。

新模块为 `support_knowledge.py`，在Graph风险节点后施加有界读取策略；查询和调用上限由应用生成，模型不能新增身份或写入参数。Runtime清单新增 `supportKnowledgeGrounding`。未训练模型、未扩大知识库，也不增加教师/重排调用。
