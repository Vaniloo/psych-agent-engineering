# GenTool 思路下的工具调用数据流水线

本文记录首批小规模流水线验证：当时未训练或替换模型。后续已扩量并启动独立 4B 实验，见[本轮训练记录](dynamic-tool-qwen4b-training-20261018.md)。运行时工具权限与正式模型未替换。

## 从论文借鉴什么

[GenTool（ACL Findings 2025）](https://aclanthology.org/2025.findings-acl.61/)的关键是让同一请求遇到不同工具集：没有适用工具→加入适用工具；只有部分能力→加入更适合的能力。论文§4.3还监督候选排序，再输出具体调用。这里借鉴其成对数据组织和排序监督，适配本项目的决策模型；不是原论文代码或成绩的复现。

本项目另加三种边界：缺必需参数时澄清；已有充分证据时停止；工具未授权时从候选中移除。简单请求也可能更适合成本低的小工具，不能把“描述长、功能多”当作固定正确标签。

## 流程与来源

```mermaid
flowchart LR
  A[显式工具契约与来源] --> B[提前冻结工具家族分区]
  B --> C[DeepSeek生成问法和描述改写]
  C --> D[Schema和参数原话校验]
  D --> E[另一轮盲审实际需求和工具能力]
  E --> F[程序构造工具集反事实与排序]
  F --> G[隔离检查与审核队列]
  G --> H[模式门控 / 候选选择 / 排序 / 独立适用度]
  H --> I[校验和冻结的数据草稿]
```

默认8个工具家族均为项目自建的模拟契约：文档修订、构建诊断、依赖审计、三维游戏资源、数据表分析、截图可访问性、游戏回放、设备手册。它们没有被注册为真实工具，没有访问真实用户、真实邮箱或文件服务，没有复用之前36例未见工具开发探针的场景。

每个家族声明弱工具、强工具、无关但相似的工具，输入JSON Schema、返回字段和相对成本。强工具必须严格覆盖弱工具；无关工具的能力不能偷偷覆盖请求。模拟执行只检查声明的参数/返回契约，不运行任意生成代码，不证明真实API正确。

DeepSeek生成四种问法：完整需求、弱工具已足够的简单需求、缺编号、无需工具的稳定知识，并改写工具描述。程序不接受模型随意扩充schema、能力或参数。参数必须能在对应用户原话中定位，保存起止位置，不从其他问法偷补。

第二轮请求只看用户原话和公开工具契约，不给参考标签；重新提取需求、参数并判断适用工具。不同意程序的声明式意图就整组隔离，不偷偷改成预期标签。两轮用同一个DeepSeek模型，错误可能相关，不能称独立人工金标。

## Softmax陷阱与训练输出

Softmax是候选间的相对归一化，所有工具都差也能出现高概率赢家。统一平移候选分数不改变概率，因此不能凭logit正负或候选Softmax最高值断言“应该调用”。现有Qwen候选间交叉熵也不自动提供校准过的绝对适用度。

每条样本导出四种监督表示，保留同一来源与分区：

|目录|任务|用途|
|---|---|---|
|`gating/`|`respond / clarify / call_tool`|独立判断本轮是否应进入工具调用|
|`selection/`|动态候选中的`next_action`|在描述驱动的候选中选择，含finish/clarify|
|`ranking/`|有并列组的排序和严格偏好对|强能力、弱能力、直接回复及无关工具之间的比较|
|`applicability/`|逐工具`ready_useful=yes/no`|独立监督“现在可调用且能补充缺失信息”，不把相对赢家当正例|

稳定知识、无相关工具和证据已足够的情形，工具适用度都是no；不是挑一个最不差的工具。缺参则模式为clarify，不能猜参数。多个工具都能补充信息时可以都标适用，再由排序区分优先级，不把所有非冠军都当作无关工具。

用户提出的“梯度下降＋删除文件/发邮件”已作为程序回归测试：不因为参数缺失就追问文件名/收件人，更不能选删除或发信。运行时仍应另做权限、副作用和schema校验；模型门控不是执行授权。这些新门控数据尚未训练或接入，不能声称当前模型已经解决该问题。

后续可给Qwen的yes/no评分增加独立二分类监督，再结合相对排序；Laya可训练独立模式任务和动态选择。是否联合优化、如何加权和设阈值应通过新的家族留出集验证。本轮不凭数据生成成功推断训练收益，也不把原始负分直接设成可靠门槛。

## 可追溯、可恢复与隔离

- `plan.json`在调用API前冻结模型、提示词哈希、种子哈希与家族分区；同目录更换计划会拒绝。
- SQLite逐次记账请求、响应、token用量和任务状态，身份由完整请求指纹确定。凭据不进入请求记录或数据集。缓存有单写者锁，防止并行生产者重复付费。
- 已完成任务命中缓存；明确鉴权/额度失败会持久阻断，不循环重试。429最多有限重试；传输超时或崩溃残留的在途调用视为结果不明，不盲目重发。不能保证远程API恰好一次，但会显式暴露不确定状态。
- 同一工具家族、对照工具集、同义问法和名称/顺序变体保持同分区；工具ID、规范化问法、完全相同契约跨分区检查。稳定ID、声明需求和参考答案不进入模型输入。
- `quarantine.jsonl`记录拒绝原因，`review-queue.jsonl`供后续抽样/人工复核；即使全部机器检查通过，仍标记`teacher_draft`、`reviewed=false`、`trainingReady=false`。
- 默认训练加载拒绝草稿，实验使用需显式允许；calibration/validation/test始终禁止用于权重训练。
- 冻结前验证数据字节SHA256、行数与隔离规则；目标目录已存在则拒绝覆盖。冻结不代表人审通过。冻结包不含密钥配置或原始教师缓存。

此处采用严格的整家族留出，主要面向未见请求/未见工具；没有把论文四象限测试全部复现。将来如增加“见过请求/未见工具”协议，要独立标识，不应把有意复用请求说成完全无泄漏。

## 小批量实际结果

2026-10-18，本地使用用户提供的新密钥、`deepseek-flash`完成16次API调用，8个家族全部通过机器检查，无隔离组；provider报告输入14,397 tokens、输出4,165 tokens。未计算货币成本。

|产物|数量|
|---|---:|
|工具家族|8|
|教师生成的基础问法|32|
|不同工具集/名称/顺序下的标准样本|216|
|train / calibration / validation / test|108 / 27 / 27 / 54|
|respond / call_tool / clarify|72 / 120 / 24|
|逐工具独立适用度正负样本|528|
|Zero-to-One与Weak-to-Strong对照对，含变体|48|

gating、selection、ranking是同216条样本的不同表示，不能累加成648个独立任务；528条适用度数据也来自这些样本。离线重放命中16个缓存任务，新增API调用0，重放前后数据字节哈希一致。

这是基础设施验收数据：8个家族、扁平字符串参数、需求较显式、只读模拟工具，表达和schema多样性仍有限。描述较工整、缺编号常直接说明，不能拿它证明复杂自然对话、MCP新工具或生产误调用率已达标。未计算生成模型准确率，未做新模型训练。

## 运行与扩展

源码入口`agent-runtime/training/toolgen/`，轻量环境需jsonschema/httpx/pydantic（也可安装`agent-runtime[training-data]`）。从agent-runtime目录运行，教师密钥通过私有环境变量传入：

```bash
# 先检查计划，不调用API
python -m training.toolgen.run --out data/toolgen/pilot --dry-run
# 默认8家族，最多20次API尝试；支持原地续跑
python -m training.toolgen.run --out data/toolgen/pilot --max-calls 20
# 只用已缓存响应，缺任务也不联网
python -m training.toolgen.run --out data/toolgen/pilot --replay-only
# 冻结校验通过的完整草稿，不覆盖已有目录
python -m training.toolgen.freeze --source data/toolgen/pilot --destination data/toolgen/frozen-v1
```

`seed-contracts.json`是可复用的种子格式。新增来源用`--seed-file /absolute/seed-contracts.json`，先明确工具家族、能力边界、输入schema、模拟参数和来源；外部契约需记录来源与准入复核。默认工具集不是不可替换的固定分类标签。当前生成器不会从任意自然语言描述自动保证工具能力。

最终MCP接入仍是：`tools/list`发现schema → 运行时注册表做权限/版本/可用性过滤 → 已授权候选描述进入模型 → 模式门控与选择 → 校验调用。MCP提供发现和调用协议，这套流水线提供泛化训练数据；两者都不能单独保证新工具语义选择正确。未来采集真实MCP schema前，还需处理缺少outputSchema、复杂参数和来源许可，并扩充工具家族、多轮观察与自然省略表达。
