# 相邻对话的小步骤进度同步 · 2026-10-16

## 问题

已保存“健康饮食”目标和两步行动，用户问“第一个小步骤是什么”，再说“OK，那我今天完成了”。实际日志中该轮 readCalls=0、goalOperationAttempted=false、synced=0，回复却说这一步算完成。`eligible_report` 原来要求当前句出现具体动作动词；后续候选匹配和后端证据检查也只接受当前句完整复述行动，无法处理相邻轮次的省略指代。

## 修改

- 允许少量明确的短状态回复进入目标检查，例如“我今天完成了”“这一步我做完了”“我今天做了一点”。疑问、未来、第三人称、引用和拒绝同步不进入这条短回复分支。
- Runtime 只在紧邻上一轮用户询问小步骤、助手实际提及且唯一对应已保存行动时绑定；序号必须匹配原 actions 顺序。检查所有已读取活跃目标，不限于模型的八个决策候选。助手内容仅用于解析指代，完成证据始终是当前用户原话，不拼接出虚构的完成陈述。
- 后端从原始 receipt 独立读取同账号、同会话紧邻前一轮，再与所有可见活跃目标逐项核对。保留原始 quote、版本锁、开关、账号隔离、幂等及撤销；两个相同标题或一次提及多步时不自动写入。
- “第一个小步骤是什么”等直接查询保证调用 get_goal_context，防止被 chat/finish 跳过。回复以保存的 action.title 为准，不合并下一步作为本步要求。
- 同步失败/未匹配也提供 applied=false 工具结果，回复须说明尚未同步并在指代不清时追问。同步成功复用既有 goal_progress SSE 和前端卡片，不新增前端协议或模型调用。

当前仍是针对相邻、可核验指代的有限补充，不代表任意长上下文或任意改述都可自动同步。复杂动作的原有模型匹配与证据保护保持适用。完成一个行动不将整个长期目标自动设为 completed。
