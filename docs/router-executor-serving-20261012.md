# Router 切换与 Executor 分工 · 2026-10-12

用户确认后，本地应用的 Router 已切到本轮微调 Qwen 4B。Executor 的工具循环继续使用 Laya v6，目标创建、行动匹配和进度类型使用独立微调 Qwen 4B。当前本地配置和 Java → Runtime 清单接口均已核对就绪；Qwen 接入保留实验标记，训练权重、校准与门槛没有改动。

目标判断仍在对话保存后进行：跳过危机、未保存轮次、非明确创建表达、非实际汇报、关闭自动同步和空候选。创建调用只请求 goal_creation；进度调用一次请求 goal_action 与 goal_outcome。模型只能选应用给出的有限候选，所有权、原话、版本与幂等仍由应用验证。目标 worker 故障或弃权时跳过写入，不再尝试工具 worker 或额外教师调用。

`EXECUTOR_GOAL_PROVIDER` 空值沿用原 Executor；指定 qwen/laya/rules 可分开配置目标 worker，独立密钥、超时与最低接受概率。分工模式下，工具客户端与目标客户端分别关闭；目标客户端不接受 next_action 请求。普通聊天、澄清路线没有可执行工具，直接结束工具循环，不再发一条仅能选择 finish/clarify 的模型请求。澄清仍由路线的回复策略处理。

运行指标从实际 `/v1/runtime/info` 的 Executor `goalDecisions` 展示两个模型的状态、实验标签和任务启用数。目标服务故障不会被工具服务的 ready 掩盖；新运行记录另含配置的 goalProvider，工具选择 trace 继续保留每一步实际模型或规则来源。

## 调用成本

对同一组 23 条工具状态，各模型重复三遍，交替先后顺序，共 69 次请求/模型。请求包含合法有限候选，串行、热身后的 SSH 往返：

| 工具选择 | Laya | 微调 4B |
| --- | ---: | ---: |
| 中位耗时 | 37.5 ms | 68.4 ms |
| P95 | 47.7 ms | 107.8 ms |
| 69 次耗时合计 | 2.50 s | 4.93 s |

同题工具选择的中位耗时降低约 45%，累计耗时降低约 49%。不能拿上一轮混合目标请求的 243ms 与本轮纯工具 38ms 比较。当前目标请求仍用 4B，178 次中位 232ms / P95 314ms；目标推理成本没有下降。

本次冻结回放有 201 个请求，23 个工具请求由 Laya 处理，4B 请求数从假设全 4B 的 201 降到 178。对应不再渲染 65/1,440 份 4B 选项输入；这个挑战目标题占比很高，不能外推真实用户节省比例。普通 chat/clarify 实际工具循环均为零次模型调用；单工具报告路线为一次 Laya 调用。真实流量的目标汇报比例与并发表现尚未测量。

本轮减少的是大模型调用量和工具决策延迟。4B 目标服务仍常驻 GPU，**常驻显存未降低**；没有使用量化、蒸馏、共享基座/适配器切换或卸载策略，也没有新增付费生成 API 调用。更进一步的显存优化应单独验证，不把当前分工的速度收益等同于硬件费用按比例减少。
