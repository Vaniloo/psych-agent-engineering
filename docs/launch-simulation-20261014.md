# 50 用户试运行场景 · 2026-10-14

本轮实际跑了最新有界 loop，未更改模型权重、阈值、并发配置或其他服务器进程。50 名测试用户以独立 JWT 账号和会话参与，普通入口仍为 **4 路处理 + 4 路短队列**。

结论是：在每人约两分钟发送一次、总体约 0.42 RPS 的四分钟混合场景中，100 条请求全部生成并保存；50 人同时发送则只有 8 条接纳并完成，其余 42 条快速返回忙碌。可以表述为“完成50账号的小规模试用场景验证”，不能表述为“支持50路同时推理”或已经验证公开生产容量。

## 使用方式与环境

- 前端代理 → Spring JWT/SSE → 最新 LangGraph loop → 当前 Qwen/Laya 角色 worker → DeepSeek Flash → 实际消息与 outbox 保存。
- 本机开发业务库为 H2 文件库，记忆为 SQLite；Chroma/Ollama 在本机，GPU 模型通过 lab SSH 转发访问。不是正式 MySQL、TLS、内网服务发现的生产拓扑。
- 复用32个专用合成账号、补充18个账号。登录/注册遵守现有10次/分钟限制，未关闭鉴权或清空限流。
- 每个账号经业务接口新建专用目标，包含散步五分钟步骤；通过真实对话保存一段个人偏好原话，获得本轮新会话。50段原话全部生成并保存。准备阶段不计入下面的容量统计。
- 50账号并行读取会话/目标页面，共100个只读请求；每账号两次读取合计P95为142ms，不能据此推导对话推理容量。

## 到达流量

日常阶段为50个用户，各有独立随机开始时间，每120秒一轮交互，运行240秒，总计100请求。请求按预定时刻发出，不用“上一条回复完成才补发”的闭环发生器降低压力；同账号不并行发送。调度延迟P95为1.27ms，未出现发生器积压。

| 场景 | 请求数 |
| --- | ---: |
| 普通聊天 | 25 |
| 心理知识 | 13 |
| 个人记忆 | 24 |
| 目标步骤查询 | 13 |
| 部分进展同步 | 13 |
| 报告/概览 | 12 |

随后50账号同时发出普通短对话；波峰完成后，选取10个被拒绝用户，以5～14秒的分散延迟各重试一次，单独统计。最后4个账号同时请求聊天、知识、记忆和目标，检查恢复。没有对全部42个拒绝请求无限重试。

## 实测结果

首字与完成延迟只评价接纳请求；过载响应不是推理成功。

| 阶段 | 尝试 | 接纳并保存 | 忙碌拒绝 | 首字P95 | 完成P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 日常交错，约0.42 RPS | 100 | 100 | 0 | 4.44s | 4.84s |
| 50人同时发送 | 50 | 8 | 42 | 4.41s | 4.85s |
| 10名用户分散重试 | 10 | 10 | 0 | 1.43s | 2.08s |
| 高峰后4路恢复 | 4 | 4 | 0 | 3.66s | 3.86s |

164次定时场景尝试中，122次接纳均生成并保存，42次均为预期过载拒绝。拒绝响应P95为235ms，带重试提示；不能将这些快速响应计入模型吞吐。日常阶段客户端峰值4个在途请求，高峰阶段为50个在途请求。服务器活跃处理采样峰值4；2秒采样没有覆盖所有瞬时队列变化。

没有观测到模型不可用、工具错误、Memory传输降级或回复中其他账号标记。8次Router低置信/未校准拒判走正常规则回退，单独统计，不归为容量故障；“没有模型不可用”不代表全部决策都由模型接受。

## 正确性核对与质量发现

- 50账号的消息增量都等于各自成功保存轮次的两倍，没有多存、漏存或把过载拒绝存成对话。
- 5次跨账号会话访问都被400拒绝。回复标记检查未发现串号；这些用例不是穷尽的隐私证明。
- 所有已接纳的指定读取场景都实际执行预期工具，13次部分进展发生真实同步。这验证工具路径与实际回执，不等于回复语义全部正确。
- 压测后另外两轮目标功能核对：普通创建与“创建目标+查询焦虑知识”各创建一个目标并保存，目标结果事件均早于首个回复token。两轮不混入性能表。
- 包含恢复阶段的25次记忆查询中有2次交付空证据，发生在同一账号和同类问题。源原话已经保存且存在于近期索引；只读单请求仍可复现。BM25没选中该原话，近期重排补入的有限候选也没包含它；单独把该原话交给4B Memory，相关性判断正确接受。优先改候选选择、重排前过滤和空证据补救，不需要先把它归因于并发或追加训练。其余请求未做独立人工全面评分，不能把23/25称为准确率。

## 复现与产物

代码在 `agent-runtime/benchmarks/launch_scenario.py`，复用 `capacity.py` 的真实SSE请求与指标解析；支持可配置代理地址。独立账号凭据、私有服务环境和原始合成回复不进入Git。

```bash
cd agent-runtime
.venv/bin/python benchmarks/launch_scenario.py \
  --env /private/runtime.env --deepseek-env /private/generation.env \
  --accounts /private/50-synthetic-accounts.json \
  --out /work/new-run --users 50 --duration 240 --think-seconds 120 \
  --base-url http://127.0.0.1:5175/api
```

账号文件需要足量的专用 `cap数字_数字` 用户、有效token和独立canary，准备过程须遵守注册/登录限制。脚本每次使用新输出目录，先检查全部模型就绪；失败或标记泄漏阻止后续阶段。普通请求不自动重试，另一个重试阶段明确单独计算。

本会话 `outputs/launch-simulation-20261014/healthy-run/` 保存逐请求、到达计划、各阶段模型清单、入场采样、消息增量、隔离检查、目标功能和记忆诊断。`report.json` 分开接纳/拒绝延迟；第一次离线诊断使用了错误环境，保留为invalid-environment产物并排除，结论仅采用校正后的只读诊断。

新增发生器测试覆盖固定到达、账号间隔、拒绝口径及代理配置，Python全套516项通过，Ruff通过。

## 上线表述与后续

可以说：**完成50个隔离账号的短时混合试用场景验证，在约0.42 RPS下100条请求全部生成并保存，首字P95约4.44秒；针对50请求突发采用有界排队与快速拒绝，保证接纳请求完成。**

仍需在正式部署拓扑做30～60分钟以上稳定性、长历史、较长回复和峰谷负载；本轮四分钟不能证明全天稳定、公开生产SLA或50路同时推理。上线前还应修复上述已知记忆候选漏召回，并使用实际流量复核回复质量。

## SSH连接复查

前一轮模型不可用的原因已确认：临时登录凭据仍有效，但SSH控制socket使用的绝对路径过长，登录后退出。改用短的相对路径 `work/lab-tc` 后恢复，所有活跃角色就绪；本报告不再将它标为密码或鉴权失败。未重启远端模型或训练。
