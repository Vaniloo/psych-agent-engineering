# 新增动态工具与叙述长句实测（2026-10-19）

后续状态：本文发现的同名多参数限制已修复，见[修复与33组回归](dynamic-tool-repeat-fix-20261019.md)。以下保留修复前的实测记录。

在本地开发环境热接入三个真正执行计算的只读 MCP 工具，没有调整模型权重或增加领域关键词路由。连同已有温度换算，用真实前端 API、Java 后端、Runtime、4B 选择器和 DeepSeek 参数复核完成测试。测试会话使用独立测试账号；测试后撤回临时账号授权，开发账号保留试用权限。没有推送或部署正式版。

## 新工具

| 注册名称 | 功能与参数 | 用户可尝试的自然表达 |
|---|---|---|
| `utilities__calendar_day_difference` | 两个明确年月日，返回带符号天数差；不含起始日 | 朋友问2026年10月20日出发、11月3日回来，前后隔几天，我怎么回答？ |
| `utilities__convert_time_zone` | 明确日期时间、来源与目标 IANA 时区；按系统时区库处理夏令时 | 纽约同事约2026年7月1日早上9点开会，我在上海，该几点上线？ |
| `utilities__summarize_numbers` | 1–200 个有限数值组成的数组，返回总和、均值、中位数、极值 | 五次耗时12、18、20、18、32分钟，其中18出现两次，一共多少、平均多久？ |
| `units__convert_temperature`（已有） | 数值及 C/F/K 枚举 | 弟弟说温度计显示77华氏度，问我平常说的摄氏温度是多少，怎么告诉他？ |

实现见 `agent-runtime/psych_agent_runtime/utility_mcp.py`。独立服务默认绑定 `127.0.0.1:18133`。通过已有主机授权清单、MCP 发现、统一注册表和刷新端点接入；没有改核心选择器或为新工具添加分支。工具描述与 schema 随发现进入模型候选。非法日期、过大列表、非有限数值、夏令时不存在或歧义时间会被拒绝，不能伪造成功结果。

## 结果与边界

27 组人工编写的开发测试中，26 组动态工具路径符合预期。包括：

- 叙述、转述和“该怎么回答”形式的真实计算请求；最长 365 字，另有 308 字统计请求。
- 票价、人数、步数、设备编号、无关温度等数字干扰。
- 负数、重复值、闰年、冬夏时差、跨日，以及同一会话修改时间。
- “原来记错了”的日期和列表数据修正。
- 一轮调用两个或三个不同工具。
- 只润色、只翻译、概念解释及缺少必要数据时，不执行这些新增工具。

实际执行了 24 次动态 MCP 调用，均由 4B 初选；DeepSeek 仍承担每次调用的语义/参数复核，因此不能说是 4B 独立完成。正常测试合计 51 次 `dynamic_read_action` 生成调用，包括参数构造、否决误选及结束前复核。完整请求中位耗时 6.48 秒，范围 4.43–10.02 秒；它包含路由、历史/记忆、工具选择、生成参数与最终回答，不是纯 MCP 执行耗时，也不是并发容量结果。

独立只给四个动态候选的评分探针中，4B 对“只润色”和“只翻译”的引用内容仍会误选计算工具；真实应用里的语义复核均否决了这些调用。缺少纽约会议日期时，4B 可识别到时区工具，但参数阶段必须要求补充日期，不能把工具初选视作可直接执行。

### 明确失败：同一工具、不同参数

> 弟弟写30摄氏度，妹妹写40摄氏度，他们分别想知道华氏温度，别只算一个。

只执行一次温度工具；回复里的第二个数由生成模型计算。虽然 86°F 和 104°F 数值正确，工具证据没有覆盖两个子任务，按失败计。

`ToolController.decide` 的 remaining 依据 `name not in results` 过滤，而 results 以工具名索引。一次成功就把同名工具排除，停止复核也只检查未调用的工具名。应另行改为“工具名 + 规范化参数”的调用去重，以及保留每次调用的观察结果；保留总次数、超时与相同调用防重复预算。仅扩训练数据不能解除此执行限制。本轮先记录问题，没有绕过去重或修改整个循环。

### 降级测试单独保留

首轮发现 SSH 连接中断，4B 不可达。该轮由现有 DeepSeek 停止复核恢复调用，23 组中22组动态路径正确；两种不同工具的请求只恢复其中一个。重建已授权 SSH 转发后才进行上述正常连接测试。没有重启服务器模型、重训或更换权重。

`degraded-*.json` 与正常结果分开存储，不能把降级成绩归于 4B。

### 未解决的成本与覆盖

新增候选使“已有一个工具结果，但还剩其他候选”更常见，很多普通请求需要一次参数生成再加一次停止复核。应基于真实失败率继续收敛复核成本。部分数字问题仍读取不相关的记忆或心理知识；测试里的“不要调用工具”只验证了不执行新增动态工具，内置读取并未全部遵循这一要求。

这些是手写开发案例，同类工具可能已出现在 ToolACE 数据中。没有工具族隔离、盲测标注或线上样本分布，不能将26/27宣称为通用新工具准确率或上线保障。
