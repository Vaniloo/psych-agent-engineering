按 2026-11-08 学习版源码核对。默认面向 AI 应用开发 / Agent 工程岗位。下面正文可以直接用于简历，项目日期按自己的实际投入填写。

## 简历正文

**Attune｜具有跨会话记忆与动态工具调用的对话 Agent**
技术栈：Python、LangGraph、Java / Spring Boot、Qwen LoRA、MCP、Chroma、BM25、SSE

独立设计并实现面向日常陪伴与目标管理的对话 Agent，支持跨会话记忆、心理知识检索、对话式目标创建与进度更新。将本地模型的路线/动作/记忆判断与回复生成分离，完成数据准备、模型微调、离线评测、服务接入及全栈交互闭环。

- **Agent 编排与工具扩展：** 基于 LangGraph 实现决定、执行、观察的有界循环，通过动态工具注册表和 MCP 接入工具；模型根据工具描述、JSON Schema 与上下文评分选择动作，宿主统一控制授权、超时、调用预算和写操作回执。
- **模型训练：** 基于公开 ToolACE 对话构建下一动作课程，实施严格调用解析、去重及共享工具名/首问/会话的分组隔离；对 Qwen 4B 进行 BF16 LoRA 微调，单轮训练 10,556 个决策状态，公开 test 示范动作一致率从 **80.65% 提升至 93.36%**。
- **记忆与知识：** 实现近期原话、分类候选、长期事实账本的跨会话记忆，结合本地相关性/充分性判断及来源核对管理更正与撤销；构建混合检索与证据核对驱动的 Agentic RAG，整理 **336 条资料、454 个片段**，支持一次补检索。
- **业务闭环与可观察性：** 实现目标创建、进度同步及反馈驱动的下一步规划；通过事务 outbox、幂等请求和所有权检查衔接保存与异步记忆更新，前端以 SSE 展示真实工具调用和处理状态。历史 50 账号交错试用中，约 **0.42 RPS 的 100 条请求均生成并保存，首字 P95 4.44 秒**。

如果简历篇幅有限，保留项目简介和前三条；并发数据可留给面试解释。不要把所有技术栈和所有历史实验塞进一段。

## 30 秒口述

我做了一个有跨会话记忆、知识检索和目标管理的对话 Agent。重点是把决策与生成拆开：本地模型决定路线、选择授权工具、筛选记忆，生成模型负责自然回复。工具通过注册表和 MCP 动态接入，我用 ToolACE 数据微调 Qwen 4B 的候选评分器，示范动作一致率从 80.65% 提升到 93.36%。同时把真实写入回执、异步记忆更新和工具可视化接通，让对话中说“完成了”能对应到实际系统状态。

## 模型方向的补充表述

如果岗位更重训练，可将业务闭环那条替换为：

> 为 Router、工具选择、Memory、长期事实生命周期和目标门控建立独立契约与评测流程，保留模型/数据 revision、SHA-256、分区清单、适配器与重载检查；区分原始正确率、拒判、错误接受及应用策略后的结果，支持候选回归和独立切换。

Weight-Space Programming 可作为研究过程补充，不建议作为核心成果：做过 LoRA 有效变化分析、激活移植、head/语义范围诊断及参数修改对照；实际修改未取得收益，因此没有替换模型。可用来说明实验设计、负结果与回归意识，不能写成“通过权重编辑修复模型”。见 [第二轮结果](weight-space-edit-round-20261106.md)。

## 不写进简历的说法

- “支持 50 人同时推理”“达到生产级高并发”：证据只支持上述短时交错试用和有界拒绝。
- “复现 JEV-Mem”“原创 Agent 算法”：当前实现借鉴决策分离与记忆控制，没有完整四视图图检索。
- “93.36% 的用户任务完成率”“任意 MCP 工具即插即用”：指标与已实现范围均不支持。
- “心理诊断系统”“已验证心理干预效果”：本项目是陪伴/支持类开发研究，没有临床评测。
