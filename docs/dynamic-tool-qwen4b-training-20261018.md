# 动态工具选择：4B 首轮训练（2026-10-18）

本轮已完成 DeepSeek 扩量、机器复核、数据隔离、冻结，以及 lab data 盘上的两轮独立 Qwen 4B LoRA 训练和自动评测。正式 Router、Executor、Memory 权重与应用配置没有替换。模型效果以服务器最终 `training-report.json` 为准；启动成功不代表训练完成或具备上线质量。

## 数据与质量控制

工具契约为项目自建的模拟只读契约，不使用真实用户聊天、邮件或本地文件。128 个预设家族分属 32 个领域，包括气象、出行、游戏运营、软件运维、学习、物流等。先按领域冻结分区：22 个领域训练，3 个校准，3 个验证，4 个测试。同家族、同义问法、名称与顺序变体不跨分区。

每个家族有 3 种语言风格，教师生成完整需求、简单需求、缺参数和稳定知识四类问法；另一轮只看契约与原话复核能力和参数。程序构造无工具→新增工具、弱工具→更强工具、弱工具足够、已有证据、权限过滤等对照。参数键名与必需参数数量有变化，不再固定为一个 `artifact_key`。

第一阶段保留 9,180 条决策记录。抽查发现部分“缺编号”问题实际是在问字段概念或查询方法，因此增加独立的、隐藏案例标签的意图复核。首版复核对“没有编号但明确想查具体记录”的请求过严，保留该版本记录，再以包含正反例的第二版审核标准重新复核。最终排除 157 个不一致问法及其全部工具集/名称/顺序变体，不改写其标签。每条可用问法仍保留原始教师请求指纹和审核来源。

| 项目 | 数量 |
|---|---:|
| 保留工具家族 / 领域 | 125 / 32 |
| 基础问法 | 1,203 |
| 决策记录（包含工具集、名称、顺序变体） | 8,709 |

逐工具记录与排序、模式监督来自上述同一批问法，不能相加宣称独立数据量。所有记录仍是 `teacher_draft`，没有伪装成人工金标。训练通过显式 `--allow-teacher-drafts` 使用实验草稿，评测分区始终禁止进入权重训练。

本轮生成及两版意图审核共 842 次 API 尝试，供应商报告输入 882,739 tokens、输出 268,913 tokens。凭据只保留在本机私有配置；没有进入数据包或传到训练服务器。单条非法 JSON 不重发，隔离后继续其他任务；鉴权、额度或结果不明的传输失败仍会阻断。

## 模型与目标函数

- 基座：已缓存并核对哈希的 `Qwen/Qwen3-Reranker-4B`，revision `22e683669bc0f0bd69640a1354a6d0aebcfeede5`。
- 从基座新建 LoRA，不在旧的固定工具 Executor 适配器上继续训练。
- BF16，LoRA r16 / alpha32，覆盖注意力与 MLP 投影；学习率 5e-5，2 个 epoch。
- 使用原 LM head 的 yes/no logits 差值给描述驱动的动态候选打分，没有新增固定工具数量的分类头。
- 联合损失：候选选择 CE + 0.7 独立适用性 BCE + 0.7 模式 CE + 0.15 成对排序。
- 模式由 respond 控制候选、clarify 控制候选和最高工具得分比较；工具得分另有独立 BCE 监督，不能把相对 Softmax 胜者直接当成值得调用。
- 训练每轮对同一逻辑状态抽一个名称/顺序变体，下轮轮换，避免把三个近重复变体当成三份独立知识。独立问法和不同工具集均保留。实际逻辑训练状态数、优化步数与 token 上限写入训练报告。
- 不静默截断；全量训练/评测输入先用真实 tokenizer 校验 2,048 token 上限。

原始 margin 不是可靠概率。适用性阈值仅从 calibration 选取，validation 检验；test 只用于最终汇报。报告同时保留共同零 margin 默认设置下的基座与候选结果、校准阈值后的结果，不能将合成域内指标当成线上错误率。

## 已完成结果与发布判断

实际训练 2 个 epoch，每轮 2,052 个逻辑状态，合计 4,104 次状态训练、514 个优化步。优化约 54.8 分钟，全流程约 71.6 分钟，峰值分配显存约 10.7 GiB。适配器 SHA256：`139b28cb80a1e2dbfd864d9a7268997c4fe0cf2b3a00e5977b7d9e0d88c1ad88`。

| 同一离线协议 | 未微调基座 | 本轮候选 |
|---|---:|---:|
| 合成领域留出选择准确率（1,095 条，含变体） | 63.93% | 99.73% |
| 不应调用时误判为调用（450 条） | 85.56% | 0.67% |
| 额外开发检查（30 条，10 个场景含变体） | 70% | 80% |

阈值只根据 calibration 选取，结果为零 margin，验证分区通过。但开发检查仍有两个底层失败场景，各三种名称/顺序变体：缺城市的天气请求没有澄清；已有真实天气结果仍重复调用。测试分区的 3 个错误也来自同一条没有显式说“缺编号”的缺参问法。以上是离线选择错误，并未执行真实工具。

因此工程复核结论为**保留候选，不替换当前 Executor**。训练分布的高分不能掩盖新 schema、真实观察值和隐式缺参场景的失败。下一步优先扩充这些数据形态、去除合成标记和固定字段命名捷径，再做新的独立评测，不以重复增加同类样本量代替修正数据。

最终原始报告和错误案例已收集到本会话 `outputs/toolgen-qwen4b-20261018/`；`release-decision.json`单独记录工程判断，不篡改自动校准门槛结果。

### 保存权重的重载与受控诊断

适配器哈希核对通过，重新加载保存的 LoRA 后，30/30 条开发检查与训练内存中的选择一致，因此上述错误可以从保存的产物复现。

诊断保持候选工具与事实内容不变：缺城市问法补一句“我还没有提供城市名称”后，错误调用变为澄清；完整真实天气结果只增加 `simulated: true` 后，重复查询变为停止；只给结果值增加 `simulated:` 前缀也会停止。空的 result 对象仍可能被误判为已经足够。这些受控输入对照支持模型使用了合成格式/显式措辞捷径，不能解读为线上性能统计。

训练分布审计也发现：132 个逻辑缺参训练状态中 131 个带有显式缺失提示词，240 个充分证据状态全部带模拟标记与模拟值，所有工具输出字段沿用 `field_0/1/2` 等通用名字。后续数据应覆盖不提示缺失的成对样本、真实形态与部分/空/失败观察、不同字段 schema，并独立保留新场景评测；不在这份已看过结果的开发检查上宣称新的独立成绩。
