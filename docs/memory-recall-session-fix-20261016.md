# 已有会话漏触发近期事实查询 · 2026-10-16

## 原因与修改

同账号一段会话陈述“最近天天吃肯德基感觉有点腻了”，另一段已有会话问“我最近经常吃什么”却答没有记录。核对已保存的实际请求：失败请求路由为 chat、loop readCalls=0、memory retrieval=null；一分钟后的新聊天仍分到 chat，但通过 thin_session 背景补充触发 memory_search，拿到了原话。

原有 personal_recall 覆盖心情、平时偏好等句式，漏掉询问本人近期经历或习惯的表达。自动背景补充超过两条本地用户消息就收缩，因而同一句话随会话长度表现不同。

本次在现有只读意图策略中补齐“本人 + 近期范围 + 事实提问”覆盖，不按品牌或饮食主题特判。识别后用明确 lookup（同账号、含当前和其他会话、近期 SQL 原话桥接），将 memory_search 作为必需工具，后续相关性、来源和证据充分性继续由原记忆流程判断。不增加模型调用或新的写入权限；泛泛闲聊的背景补充仍有限额。回应提示补充直接回答事实、避免固定的来源开场。

这仍是有限句式的能力保障，不代表已经解决所有自然语言回顾意图。陈述、建议、未来计划、引用和拒绝查记录不因本次改动升级为此类 lookup；新增负例覆盖“没什么胃口”“做什么都没意思”等含疑问词的陈述，避免误作纯提问丢弃证据。
